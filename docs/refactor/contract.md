## 2. 产品、平台与兼容边界

**已确认。**

| 范围 | 结论 |
| --- | --- |
| 主体 | 多通道共享同一主体，连续前台、独立反思、显式行动才产生实际输出；最终模型文字不自动发送 |
| 输入来源 | 没有主人/来宾等级，不建立能力许可表、目标授权名单或人工审批；不迁入跨通道身份关联系统，来源表示见第 4 节 |
| 旧数据 | 旧 Runtime 仅内部短期测试，不迁移原文、认识、会话或诊断数据；旧文件不自动删除 |
| 旧主配置 | 保留 TOML，可重整结构，不兼容或转换旧格式；提供新示例 |
| 插件源码接口 | 可以重新设计，不建设旧 Runtime Python 插件兼容层；不等于随意更改模型工具或外部设备协议 |
| 其他公开 Python API | Engine 不兼容旧 Runtime 的全部公开 Python API，不建设旧 Runtime/Application/World 等转发层；Core/LiteLLM 公共接口不在此破坏性授权内 |
| 装配 | 插件与活动定义只在启动时装配，变更通过重启生效；连接重连与活动启停仍可在运行期进行 |
| 平台 | 首版正式验收 Windows 本机完整能力；其他平台暂不承诺。基础代码保持平台无关，具体 Python/SDK 组合待冻结 |
| 发行 | 一个 Engine Python 包包含内置插件、WebUI 静态产物及调音室入口；设备依赖按需安装、配置显式启用；Core/LiteLLM 独立依赖，Design 为规范/组件来源 |

启用但缺依赖应在装配前明确报错，未启用插件不加载可选原生库。运行不自动安装依赖。外部插件可独立成包，通过明确配置入口接入；不建设插件市场或自动启用扫描。WebUI 构建发生在开发/打包时，安装后的使用不要求 Node 开发服务器。调音室独立命令运行，不启动主体。发布产物须独立于本机兄弟源码目录。

新公开 Python 面保留程序式嵌入：宿主配置/启动/关闭、输入接管与结果等待、状态/证据查询、已确定的插件/能力/执行器扩展及必要值/错误类型。内部调度器、通用可变存储不因旧包导出过就继续公开。旧示例与调用者按新入口改写；精确签名随整体设计审阅，等待超时与真实执行终止保持区别。

### 常驻宿主及命令行运行方式

**已确认。** 正常启动采用常驻宿主入口，例如 purrcept-engine run：加载配置、取得数据目录锁，启动已配置服务/本机 WebUI，保持运行直到显式退出。打印本机面板地址，不要求浏览器页面保持打开；不因没有控制台输入而退出。具体命令拼写属于后续交付接口整理。

控制台文字输入是可选的宿主内接入适配器，启用后与 QQ/语音共用同一主体及显式输出规则。标准输入 EOF 只停止控制台读取并标明输入端已关闭，宿主继续服务其他通道；/quit 或 CLI Ctrl+C 才请求整个宿主正常关闭。EOF 不等于终端窗口被操作系统强制关闭，后者仍可能导致进程中断，不能声称进程可脱离任意终端终止继续存在。

首版不迁入旧 ask 子命令的“一次提问即启动宿主、返回后关闭全部资源”模式，避免把持续活动和连接寿命系在一次回复上。程序式嵌入仍提供提交/等待与显式生命周期入口，单次使用由调用程序决定何时关闭；不以另起一个同数据目录宿主充当常驻实例的客户端。当前未增加独立远程控制台或网页聊天通道。

配置示例生成、纯配置校验/插件声明查询、独立声线调音室仍分别提供入口；这些操作不为了复用 CLI 而启动主体或打开设备。旧 Runtime CLI 命令不做兼容转发，交付文档给出新启动/校验/退出用法。依赖旧 ask 命令的脚本需改用新程序式入口，常驻生命周期由宿主入口拥有。

## 3. 模块、依赖与状态所有权

**委托设计。** 以下是职责区域，不强制每项建立独立包、Protocol 或转发服务。

| 区域 | 拥有的职责 |
| --- | --- |
| app | 配置、实例锁、资源装配、CLI/WebUI 接入、启动关闭 |
| subject | 输入与注意、前台/反思调度、计划、活动控制、认识规则 |
| context | 已选材料与目录组装、实际请求容量检查、历史摘要安装 |
| execution | 目标/能力目录、逐次调用、并发与生命周期约束、Worker、真实回执 |
| storage | SQLite/媒体、查询及原子业务提交，格式与版本核验 |
| plugins | QQ/浏览器/语音/身体协议及资源；闹铃/笔记等各自业务规则 |
| web | Design 规范下的观察与快捷控制，持有可失效展示快照 |

app 负责组装。subject/context/execution 不导入具体内置插件；storage 不导入应用入口或设备。插件依赖明确登记与执行/反馈端口，界面借用应用入口，不访问数据库或持有设备客户端。不存在通用事件订阅隐式完成必需步骤的主流程。

主流程：插件解析输入 → 入账原文与待处理状态 → 注意调度 → 组装材料 → Core 推进会话 → play_action → execution 调用插件 → 保存真实回执 → 继续会话或保留失败经历 → 独立反思及后续交互。

- Core Conversation 拥有已提交历史。Engine 会话适配对象拥有串行使用、生成代次、检查点及请求证据；前台与反思不共享可变历史。
- 执行服务拥有行动与逐次能力调用的真实结果，不依赖会话提交是否成功。Worker 自报结果不能覆盖真实回执。
- 反思提出认识变更，提交入口核验来源/版本；前台和插件不直接修改认识。
- 活动宿主独占活动控制状态提交；驱动拥有局部流程/工作检查点，只报告事实和确认。
- 插件拥有连接和临时采样；正式接管媒体归权威存储。UI 关闭不释放设备。
- World 收敛为对象与能力目录，保留实际设备/应用包含关系及稳定绑定。闹铃、休息和笔记状态归各自模块；不维护第二份可写权威状态。首版不迁入通用关系图、物品转让或可见名单共享。
- 模型目录与执行使用同一套已校验绑定。包含关系与路径生成有明确规则，不在多处手填重复结构；精确模型路径变化仍须审阅。能力存在不代表设备当前在线。

修改场景检验：新增 QQ 方法主要改 QQ 定义/登记；摘要规则改 context；控制确认改活动宿主及提交入口；更换音频驱动不牵动主体编排。抽象必须承载这些实际变化，不能只转发调用。

### 宿主入口与插件资源契约

**委托设计。** 宿主对嵌入调用者提供 start、submit、wait_input、query、control、close/wait_closed 等职责明确的入口；名称为工程设计，不是新增模型工具。start 返回核心就绪及外围状态，不保证所有外部服务在线。submit 只有在原文/媒体与待处理状态原子接管后返回 accepted/input_id；重复来源身份返回已有接管记录。wait_input 观察该输入的处理状态与实际输出/行动引用，不将模型最终文字自动转为对外回答，也不等待与其有关的一切长期活动结束。取消或超时只结束本次等待，不撤销已接管输入或行动；查询可以继续取得结果。

control 使用与已确认 WebUI 相同的业务控制入口，受理和实际完成分开。query 不启动设备或模型，返回带宿主实例/版本的不可变快照。close 关闭全局新工作入口并等待同一收尾任务；重复调用加入该任务，不重新触发插件清理。达到已确认总期限返回未完成与仍占用资源，可继续 wait_closed；仍有活跃借用、未结束关闭或未确认资源释放时不能报告 closed。库入口不退出调用者进程。

插件接入分为纯声明、装配和运行三个阶段。声明给出身份/依赖、配置类型、对象/能力路径和活动定义；配置校验及完整目录生成不需要打开网络或设备。app 按已核验依赖构造资源所有者，将能力实现绑定到声明，检查缺失或重复绑定；全部目录与主体输入接管入口准备好之后才启动外部接入，不通过订阅“主体已注册”事件来补齐必需装配。设备显式连接/收音仍服从既有启动规则，不因插件 start 自动采集。

| 插件生命周期入口 | 调用与所有权契约 |
| --- | --- |
| declare / build | app 在启动装配期调用；声明无外部副作用，build 接收已校验配置与显式依赖，返回本实例所有者及绑定。不允许持有通用可变主脑/数据库对象 |
| start | 装配完整后由宿主调用一次，建立该插件配置要求的接入任务；已知外围暂时不可用报告离线，内部异常保留失败。后台任务登记到所有者，不产生无人负责的 create_task |
| stop_ingress | 宿主关闭时阻止新输入/采样/恢复尝试；保留在途请求响应与真实回执通路。必须区分业务输入接收和传输接收，不能为了停 QQ 新消息而先杀掉发送回包 |
| close | 宿主确认相关借用已结束后调用，按依赖逆序释放实际资源；重复等待同一关闭进度，不盲目再次执行部分失败的 close。没有相应资源的插件无需实现空转生命周期层 |

这些阶段用于隔离真实复杂性：纯校验与资源启动、完整能力目录与外部输入、停止新工作与收回资源。无需每个阶段各建一个类，也不再实现产品未需要的运行期插件热替换。资源取得后立即由其所有者登记；部分启动失败同样保留已取得资源的清理任务与结果，清理失败附在启动错误上，不以清空引用冒充回收完成。清理等待失败的资源不能自动重建另一实例与其并存。

依赖由 app 显式注入：输入接管、受控能力调用、活动反馈、只读状态以及必要的专用业务存储操作分别有契约，不提供按任意字符串查找一切服务的入口。音频可向身体发送实际播放进度，但音频组件不依赖身体在线；身体借用音频进度，不能拥有播放。注册出来的能力输入/输出仍需真实边界校验；上述注入用于表达职责，并非恢复人员权限系统，也不承诺将第三方 Python 插件沙箱隔离。

### 输入确认与迟到反馈

**委托设计。** 接管、材料交付、主体处理结束和实际效果分别记录。插件提交后持有 input_id 与来源会话/代次，宿主从实际注意/前台状态产生处理通知；明确选择仅记录的输入可以结束处理，延后输入保留延后状态，失败不得冒充成功。模型看到材料不等于已经理解，处理结束也不等于说过话或执行过动作。通知丢失或接入重连可按 ID 查询，不因缺少 UI 通知重投同一外部输入。

插件回传携带对应 input_id、call_id 或 command_id，以及来源连接/运行代次；宿主验证是否仍能更新当前状态。迟到截图不能替换新连接预览，旧控制确认不能复活已结束活动；已经实际发生的发送/播放结果仍归入原调用记录，不因代次过期删除。过期结果能作为历史事实保存，与它能否驱动当前状态是两个判断。宿主完成确认不通过模型自然语言、工具相关 ID 的字符串前缀或某个展示回调推断。

### 模型能力目录与稳定前缀

**已确认。** 完整前台能力目录作为前台 system instruction 的稳定部分，每次前台实际请求保留一份当前定义，以形成可复用的缓存前缀。目录包含已装配能力的调用路径、说明、输入约束、必要使用语义及示例；目录与执行绑定来自同一声明。首版无需先搜索能力再读取 schema，也不因容量不足自动隐藏一部分已启用能力。技能概要与可编辑技能正文仍按既定规则提供，不混入固定能力契约。

**委托设计。** 固定人格/工程规则与完整能力目录组成连续稳定前缀，历史和当前输入、状态、预算等动态材料放在其后。目录在声明装配完成后按确定顺序生成，同一声明/配置产生相同文本与 schema 顺序；不得将时间戳、随机请求 ID、实时状态或剩余预算混入此前缀。顶层工具 schema 与顺序同样保持稳定。设备断线只改变后续状态材料，不删除目录项；声明/路径/契约真正变化时才生成新目录版本，不沿用失效的缓存内容。

用 Core SystemInstruction 的稳定性标记及现有缓存策略表达意图，Purrcept LiteLLM 的请求编译负责实际 system 消息与支持的缓存提示。当前适配中的普通 SystemReminder 即便 placement=INSTRUCTIONS 也仍是 user 消息，不能用这种放置方式冒充目录已进入 system。动态材料优先放在历史之后，避免不必要地扰动可复用的历史前缀；精确消息布局仍须在实际请求基线中核对。

目录只包含装配时受控声明的使用契约，外部聊天、网页、笔记正文或设备采集内容不因靠近目录而进入 system。历史重复/旧目录以可追溯版本引用保留，已执行调用的旧参数和回执不改写。提升目录到 system 会改变模型输入层级，需单独验证，不称为无行为影响的格式调整。

稳定前缀不等于服务端必然命中缓存；具体端点支持、缓存有效期与用量须验证，不预先承诺成本降低比例。缓存命中不能免除上下文容量计量。模型侧缓存与 Engine 的原文/请求保存是不同机制，不因命中或缓存失效改变原文保留。首版不自建模型响应缓存或通过复用旧回答省略应发生的新推理。

### 实际请求的材料布局

**已确认。** 前台生成请求按以下顺序组装；原始请求另行保存，使不进入会话历史的动态快照仍可追溯。

| 顺序 | 内容与更新方式 |
| --- | --- |
| 固定 system 前缀 | 保留仍适用的人格/工程语义、已确认的新契约和完整前台能力目录；按声明确定顺序，不加入实时状态 |
| 连续历史和本轮过程 | 已确认的历史/摘要，当前输入的来源与实际正文/原生媒体，以及本轮正常工具调用/结果，按真实先后保持；已交付的本轮输入不每次重新注入 |
| 当前状态尾部 | 当前活动/未决关键行动、承诺与监管、设备可用状态、技能目录及本轮预算；每次逻辑模型请求前取得一个带版本/时刻的快照，替换上次尾部，不反复写成新的历史发言 |

当前输入属于有来源的外界材料，尾部属于宿主状态投影，二者不混为同一种发言或提升为 system。必要行动回执按已确认保护规则提供；同一结果已在工具消息完整交付时，尾部只提供关联与当前未决状态，不重复复制全部正文。历史状态保留其当时含义，尾部表示组装时实际状态；它不能推翻已发生事实。发送后状态仍可能变化，执行前继续核验真实状态，不能把提示快照当作启动许可。

反思沿用同样的静态规则、独立历史和动态尾部区分；只提供已确认的五项反思工具契约，不复制前台完整世界行动目录。本批原文/覆盖清单作为批次输入，后续展开记录实际已读片段；待复核状态和预算更新在尾部。注意判断没有连续主脑历史、世界行动目录或工具，只取得第 4 节定义的当前输入和有限相关工作材料。

**委托实现依据。** Core ReminderSource 可在每次逻辑模型请求编译时同步产生请求局部提醒，不写入 Conversation 历史；Engine 使用已提交状态的内存快照，resolve 不访问数据库、设备或网络。LiteLLM 当前将尾部提醒编码为 user 消息，因此必须明确标注宿主状态来源及其中嵌入文本的来源；不把提醒名称当成 system 权限。重试同一逻辑请求保留同一材料快照；剩余实际期限仍由宿主核验。新方案需比较实际消息顺序、工具结果关联、固定前缀及容量计算，不能仅验证字符串模板。

### 模型能力调用契约

**已确认。** 保留 play_action(action_code) 与 from world import me、await/关键字参数的行动调用习惯。对于保留且语义未变的内置能力，沿用其模型可见路径与关键参数名，例如 me.phone.qq.send(chat, target_id, text)；这是 Engine Worker 提供的虚拟接口，不要求保留旧 Runtime 包或 Python 公共 API 转发层。部署实例可通过明确装配形成不同对象路径，实际目录始终给出精确路径，模型不靠目录名推测。

已确认行为变化所需的参数明确调整：长文读取的续读信息、笔记修改版本、语音可选身体表达、活动受理/确认结果等；旧权限/身份关联字段不迁入。对必要破坏性调整只提供新契约与清楚示例，不维持语义冲突的旧字段别名。已确认的必要接口包见第 9 节，屏幕 react 删除见第 7 节；未列出的新变化仍须审阅，此方向不是所有旧工具逐字段兼容或任意改名授权。

## 4. 输入、注意与连续会话

### 接收和积压

**已确认。** 人类发言、行动回执和正式业务事实逐条保留身份、来源、时间与原文，可以合批思考，不要求逐条回复。连续环境状态在尚未接管阶段可更新同流最新候选；已入账、已用于模型请求或显式截图所得证据不能被覆盖。用途与替代范围由接入代码声明，不靠正文猜测；未知材料默认不合并。

接收与模型处理解耦，有限工作任务读取可靠待处理记录。积压数量/字节、模型并发与上下文容量分别约束。无法接管时明确减速、暂停或拒收，不删除最早聊天伪装运行正常。语音过载说明未接管缺口，不拼凑残缺文本；QQ 回包接收不能被业务队列等待堵住，断线不保证上游补投。

**委托设计。** 输入信封分别保存 host input_id、适配器原生事件标识、平台发送者/会话范围、发生/接收时间、原文、媒体引用及注意依据。QQ 消息去重使用适配器实例、账号、会话范围、事件类别和原生消息 ID；不以文字相同去重。来源没有可靠事件标识时生成接收标识，并明确无法保证跨连接重放去重；不发明时间窗散列来合并合法重复事件。重复接收返回原接管结果，原文与待处理记录不分开提交。已使用事件标识带来冲突内容时显式报告，不覆盖旧证据；合法编辑须由适配器声明为更新事实。

### 输入来源与麦克风身份名

**已确认。** 不迁入跨通道身份关联子系统，不设置统一参与者档案、账号映射、身份合并或关联版本机制。麦克风输入只附带一个可配置的身份名，作为主脑可见的发言来源；配置按既定主配置规则加载，不引入说话人识别或身份验证流程。

QQ 保留平台发送者信息，控制台保留本地控制台来源；原始通道、会话位置、事件标识与回复路由仍用于追溯、去重和投递，不承担跨通道人员绑定。麦克风身份名不与 QQ 账号自动匹配。旧 DialogueService 的账号/person 映射与角色逻辑删除，仍需要的路由和状态查询交回所属输入适配器与宿主入口，不保留一个空的身份服务层。

### QQ 自动接收范围

**已确认。** 保留可配置的群聊/私聊纳入或排除范围，以及跨会话忽略指定发送者的入站过滤；默认接收已连接账号实际收到、协议可解析的全部群聊/私聊消息，不凭此承诺读取平台未推送的历史。它决定自动接收哪些来源，不对人划分权限等级，也不授予或禁止能力。主配置静态加载，变更按已确认重启策略生效；不为过滤列表增加独立热更新平台。

源过滤在正式接管前执行，被排除的推送不保存正文/媒体到主体权威经历，不进入注意判断或反思，也不因直接 @ 绕过范围。有限诊断可记录来源标识、时间、过滤原因或计数，不保留被排除的正文作为隐藏档案。已在先前配置下正式接管的历史不因修改过滤设置而自动删除。平台回包、已经开始的行动回执仍走各自接收路径，不被业务消息过滤误丢。

保持现有边界：入站过滤不限制主脑显式调用读取历史或发送的能力，也不是不可接触某人的全局名单。被忽略发送者的内容仍可能出现在其他正常消息的引用/转发或主动历史查询中；不递归删改这些原文，保存真实来源。若未来需要彻底屏蔽某一来源，则必须另定涵盖查询/引用/发送的产品语义，不能借入站配置隐式添加权限系统。

接收不等于回复：已接管的普通群聊继续由注意判断和主脑决定是否处理/表达，直接 @ 的最低唤起只在已接收范围内生效。示例：群 A 被排除时，其实时推送及 @ 不进入主体；主体因其他已接管事项显式查询群 A 历史时，按该工具真实结果入账，而不是宣称从未能访问此群。无需这类范围控制时可保持默认全接收，但仍受明确的资源/协议边界约束。

### 注意与抢占

**已确认。** observe 表示记录，defer 表示有到期依据的复查，wake 表示下一次思考，urgent 撤销当前生成资格。它们不直接执行世界动作。

- QQ 协议确认的直接 @ 至少唤起，不强制回复。
- VAD 达到配置中的持续人声门槛后，音频所有者直接受理停止当前合成/播放并取消当时的候播，同时提交生成抢占信号；不等待最终转写或主脑调用停止工具。此规则仅限现场音频，一般 urgent 仍不直接执行世界动作，QQ 发送和其他活动不因此被取消。转写/原音仍正常理解，不恢复语义停止词路径；短噪声未达门槛不触发。
- 文字聊天的停止意图由上下文判断，取消角色专属关键词捷径。正文自称 urgent 不成为调度字段。
- 已开始行动独立于生成继续。除已确认的 VAD、宿主关闭和明确外部控制外，停止播放/暂停活动由主体显式执行；WebUI 明确控制直接提交，不必等待模型。

**委托设计。** 文字判断材料包含会话/@/回复关系、有限相关交互与工作摘要；缺失引用保持未知，截断不得消除否定等必要语义。最低 WAKE 先保证待处理，旧生成仍在运行时可作紧急升级；判断绑定所观察的生成版本和输入状态，迟到结果不能取消已在处理同一输入的新轮次，也不重复入队。材料完整性与实际请求布局依本节及第 3 节执行；实现时核对最终提示，不增加新的判断职责。

注意服务的预期超时/不可用在有限尝试后，携带失败标记把材料交主脑一次，不当成 observe。内部程序/权威存储故障不伪装成正常判断；故障记录不循环唤醒，主脑再失败按普通失败接续。不配置语义门控时明确标记未筛选，不伪报模型判断成功。

正常 VAD 中断是预期控制结果，不仅因这一结果就立即反思；真实设备/执行异常仍按异常规则处理。VAD 停音沿用真实回执及迟到音频不得播放的约束，阈值沿实际配置。音频停止和生成抢占分别记录同一输入的因果关联；其中一项失败不能伪报另一项未发生。“不等待模型”不等于零延迟，实际停止延迟需要实机验证。

### 注意判断的材料完整性

**已确认。** 注意判断的筛选对象是已接管的当前输入：向所配置后端提供完整当前正文、来源/会话/@/回复关系及其支持的原生媒体。这里完整指实际取得的当前材料，不自动抓取链接页面、补采其他画面或展开外部历史。原生音频仍按所选输入模式处理，不为适应注意后端偷偷新增 ASR、OCR、图像描述模型或其他媒体转述步骤。

普通输入继续合批，容量按实际正文和媒体计量；一批装不下时先减少该批条目，保留其余条目的待判断身份，不剪每条开头来制造可用请求。单条仍无法完整容纳、媒体不受该注意后端支持或实际材料缺失时，不以其残缺预览得出 observe；记录未完成筛选的具体原因，将该输入交前台一次，不额外尝试另一注意模型，也不绕过前台容量检查。语义明确的最小唤起和 VAD 快速路径保持既定规则，不等待此判断。

工作背景仍为有限相关交互与当前正在处理的输入、活动/承诺、进行中行动/音频状态，不复制完整主脑历史或隐藏推理。背景条目的省略范围与缺失引用明确标示，不冒充完全掌握场景；当前输入与背景覆盖分别记录。判断不能以未取得的引用正文或未读媒体为空来推导无价值。返回 observe 只表示本次有限语境下选择记录，不保证模型语义判断正确。

成本取舍：相较旧 1000 字预览/附件数量，完整当前材料可能增加注意请求费用；小窗口或不支持媒体的注意配置会将更多输入交给前台。不保留仅凭正文开头和媒体数量就完成筛选的路径，避免未读长文后部或媒体内容被直接判定无需思考。没有加入新模型或自动路由，费用效果需真实场景验证。注意合批时长、批量和 defer 初值见下节已确认调度约定。

### 注意合批与延后复查

**已确认。** 保留现有数量级，将三个调度参数集中配置：普通输入合批窗口初值 100 毫秒、一次注意判断最多 8 条输入、注意 defer 延后初值 30 秒。100 毫秒可设为 0；批量为正整数，延后为正的有限时长。实际批量仍受完整材料容量限制，不为凑够 8 条额外等待。该批注意判断仍按现有“整批最高必要级别”处理，逐条保存来源与处理状态；不在本次添加逐条分类调用。

合批窗口从当前待组批输入中最早一项的接管时刻起计算，后来输入不刷新截止时间。注意工作器串行，已有积压超过该窗口时立即组批，不再固定睡眠；组批时冻结共同工作背景及每项原文引用，判断期间的新输入留给下一批。注意结果进入前台后不再叠加第二段 100 毫秒合批等待；前台当时正在工作所需的排队另计，不保证总响应只有 100 毫秒。可信最低唤起和 VAD/明确紧急路径不等待普通合批；在已确认的紧急升级规则下核验目标生成代次。

defer 由宿主在判定提交时设置并持久化到期时刻；到期将原 input_id 和原文直接交前台一次，不再进入注意判断，因此不能由注意层不断延期。投递资格、原输入 pending 状态和到期记录的已交接状态在同一事务更新；通知/进程中断不能造成漏投或重复执行。若该输入已被明确纳入并完成前台处理，则关闭对应延后项；仅因文字相似不算已处理。重启后未到期继续等待，已到期而尚未交接的补投一次，附原定时间及延迟。

这里的到期只保证进入前台待处理，不承诺立即发言、执行动作或打断当前生成；同批可以合并多个到期事项，但保留各自输入身份。前台失败或预算耗尽沿已确认的失败经历规则处理，不自动重建一条 30 秒延期来重置预算。主脑 plan_wakeup 和反思 deferred 是不同的业务记录，不能共用注意 defer 的默认时长或把它们也变成自动反复判断队列。

### 模型请求、错误与失败经历

**已确认。** Core 管会话/工具循环和整轮提交，Engine 管主体/上下文/证据及单请求恢复，Purrcept LiteLLM 管供应商转换、流聚合与错误。Engine 不复制工具循环。

- 临时模型故障仅在当前有效轮次内有界重试同一次请求，次数和总时间统一控制；不重跑已经执行的工具或整轮。底层 SDK 可配置重试显式收敛，不能叠加不透明尝试。
- 流式半成品不执行、不提交为正式助手消息、不与重试结果拼接。已有工具回执继续供本次请求使用；取消、关闭和存储故障结束重试。
- 未知工具、参数错误、行动语法错误和明确版本冲突可返回模型，由其在现有预算内纠正；内部故障不可全转成“请模型修参数”。失败/未知世界效果仍真实记录，不自动重放。

**委托设计。** 失败原输入、失败位置、已确认/未知效果及来源作为“失败经历”参加下一次正常交互，不再次作为执行命令投递。正文/回执可引用展开，但当前所需关键事实必须可见；失败生成的说法不冒充实际发言或已完成效果。材料接续与输入终态同事务保存。接入方等待超时只结束其等待，不伪报主体或已开始行动终止。

### 模型请求重试与等待预算

**已确认。** 仅对可识别的暂时不可用、连接/请求超时和临时限流重试；已知凭据错误、无效请求、不支持参数、上下文超限、明确额度耗尽、模型正常拒答、响应结构不合法及内部异常不做传输重试。限流若没有足够信息区分额度耗尽，可按未知原因限流有限尝试，不据此修改凭据或更换模型；平台错误分类不完整需如实保留原因。

初始配置如下，均可由 TOML 按模型用途明确调整，不要求所有模型采用同一延迟假设：

| 用途 | 总尝试上限（含首次） | 每次尝试上限 | 同一逻辑请求总上限（含退避） |
| --- | --- | --- | --- |
| 前台、反思和历史摘要的生成请求 | 2 | 120 秒 | 180 秒 |
| 注意判断请求（专用判断或聊天实现） | 2 | 5 秒 | 8 秒 |

无有效服务端等待建议时，第二次尝试前等待 1 秒；存在可用 Retry-After 时至少等待其指定时长及本地 1 秒退避。等待已超过剩余总时间则直接结束重试，不提前重打。每次尝试还受逻辑请求和上层轮次/活动剩余时间限制；实际截止取最早者，第二次不保证取得完整的单次额度。这些数值尚未经真实模型延迟验证；不能将旧整轮 120 秒等同于新单请求上限。整条工具轮次预算独立约束，不能因逐请求重试而解除总约束。

已收到部分流式内容后若发生可识别的临时网络故障，可在同一预算内重新请求，旧片段仅保留诊断证据，不执行、不拼接。尝试数/等待可观察，取消、抢占和关闭终止等待；已经完成的工具保持真实回执，不因生成重试重做。注意判断耗尽后按已确认规则携失败标记交主脑，前台生成耗尽保留失败经历，不后台无限重试。超时撤销采用资格，底层无法及时取消时迟到结果不执行，也不声称服务端已停止计算。

Engine 负责唯一的可见重试循环，适配处显式关闭能够关闭的 SDK 自动重试并验证实际网络尝试数。当前本地 LiteLLM 的 OpenAI 路径存在 max_retries 分支，不能只传一个顶层参数就宣称所有端点已关闭；专用判断及其他 Provider 路径尚需分别检查，不修改全局 SDK 状态。

### 整轮思考预算与耗尽边界

**已确认。** 前台一次输入批次的连续思考、反思一次批次处理，分别初始最多 8 次逻辑模型请求、总计 600 秒，可按用途配置；两者独立计量。一次逻辑请求内的传输重试不另占模型轮数，但占用其请求预算和整轮时间，因此 8 次逻辑请求在已确认重试策略下最多 16 次 Engine 可见尝试。一个响应可含多个工具调用，受限 Python 中也可组合多项能力；8 次不是能力调用数或对外发言数。摘要仍走无工具单请求预算，不借整轮额度额外循环。

整轮时间从该批次开始主动处理计至结束，包含材料组装、模型等待、退避及本轮工具等待；输入排队与注意判断不占该轮时间，它们分别有既定边界。数值只作为初始配置，未证明所有真实场景都能完成。前台和反思的同一因果续行不能通过重新包装批次或自动自唤醒重置预算；新外部输入或独立新事实的接续仍按输入/反馈语义处理，不把新事实永远并入旧预算。长活动维持自身预算，不占用一条无限前台循环。

请求中提供本轮已用/剩余逻辑轮数和剩余时间，以及最后一轮须结束而不能新增工具的说明。每次实际派发仍核对真实预算，提示中的剩余时间是请求组装时的快照。沿用 Core run_model_turn 的边界：最后允许的一次响应若无工具则正常结束；若仍提出工具，先报轮数耗尽，不执行该响应中的工具。正常最终文字仍不自动对外发送，也不额外发起一次无预算的模型收尾。

时间或轮数耗尽撤销本轮生成资格，禁止再启动由该轮新提出的行动；保存已确认/未知回执、失败经历与未执行提案的区别。它不撤销已经实际开始的独立行动，也不因前台超时自动暂停其他活动；在途行动仍受自身资源/关闭规则约束，真实结果继续入账。反思已提交的认识仍保留，未完成批次不能标记复核完成。耗尽事实本身不触发无限自动续跑，符合已确认的后续交互接续规则。

## 5. 上下文、认识与活动

### 历史容量与技能

**已确认。** 旧历史可自动摘要，原文可追溯；近期交互及关键回执受保护。必要材料仍装不下时明确报告，不静默裁剪。摘要触发阈值是配置值，默认 0.8。完整证据、当前选择、语义压缩是不同职责；模型窗口、输出预留与容量估算按下文约定。

权威原文长期保留与材料常驻当前窗口是不同承诺。保护近期完整交互及仍影响当前判断的关键事实：

| 材料 | 当前窗口保护方式 |
| --- | --- |
| 当前输入、未提交工具轮次、近期完整交互 | 不纳入旧历史摘要；必要多模态材料仍按本次输入契约提供 |
| 未结束活动、未完成承诺、待确认控制、未处理失败经历 | 保留明确状态、来源及继续处理所需内容，不仅依赖历史摘要 |
| 已发生但相关事项未处理完的效果、未知外部调用 | 持续提供宿主从真实记录生成的关键事实：调用/目标、关键参数和平台回执身份、确认/未知状态及待核对之处，关联完整原文 |
| 已处理结束且离开近期窗口的旧交互/回执 | 可进入有来源摘要，不永久全文常驻；原始输入/结果仍可展开 |

关键事实不得被摘要模型改写。巨大返回值可以引用，但本轮判断需要的正文/图像必须展开并计入容量，不以空引用冒充必要内容。事项关闭以实际终态、明确处理记录和来源为依据，不因时间、邮箱确认或模型自然语言“完成了”退役保护。主体可结束继续追查，但未知事实仍保持未知，不能据此重放。

示例：QQ 已发送、后续处理失败，后续交互仍明确看到已发送及真实回执；有关事情处理结束且离开近期窗口后可摘要。未决事项积累过多仍报告容量不足，不为腾空间伪造已解决。

主脑和反思各自默认保护最近 2 个已完成的完整交互轮次，另保护当前尚未完成的轮次。完整轮次包含该次输入、全部中间模型响应及工具结果和最终内部响应，不按单条消息、单次模型请求或外部发言计数；摘要占位消息不算新增真实交互。失败经历和仍未解决的关键事实按既有规则独立保护，不因离开两轮范围而消失。保护轮数可配置，不能为满足摘要目标临时减少。

以所选模型的可用输入预算为分母应用摘要触发阈值；摘要目标可配置，默认 0.5，且低于触发阈值。比较本次拟提交完整请求的容量计量，包括指令、工具 schema、目录、必要材料和保护事实，而不是只看历史消息。本地比例不宣称精确等于 Provider 用量。

50% 是维护目标，不是安装硬门槛。近期/关键材料使其无法达到目标时，只要摘要来源与保护约束成立、完整候选请求确实缩小且仍在输入预算内，就允许使用；例如 80% 降至 60% 可以接受。不因目标未达而反复压缩同一份来源、缩短受保护材料或删除原文。同一来源在没有新增可压缩历史时不重复启动模型摘要；无效或失败摘要保留原历史，按已有失败/容量规则显式报告。

摘要触发阈值用作提前维护触发值，而非暂停线；尚未取得摘要但完整请求仍在预算内时可继续。真正超过预算时须先完成有效维护再继续；维护后必要材料仍超限则明确容量不足。新增巨量输入可能直接跨过预警阈值，因此每次实际请求仍需检查，不以曾做过摘要保证后续都能装下。旧原文长期追溯与模型摘要质量验证规则保持不变。

**委托设计。** 摘要计算使用冻结来源、无工具模型请求；不推进反思的连续 Conversation。摘要带来源版本和覆盖范围，仅在目标会话空闲且版本仍匹配时安装。归档、候选检查点和摘要关联同事务保存成功后才替换内存历史；提交失败保留旧状态，版本过期丢弃提案，不让它覆盖新轮次。安装期间暂不推进该会话，输入仍可接收。记录变化后的实际请求用于基线，不宣称重新表示历史对模型必然无影响。

技能目录自动呈现名称、适用说明、路径和读取入口，正文按需读取，主脑自主决定采用。普通笔记不全部注入；写技能不自动执行，不变成已核实认识。Notebook 管文件与目录，上下文消费其只读快照；已读正文留证据，之后文件修改不抹掉历史。目录仅包含本段已确认信息；需要新增模型可见语义时另行讨论。

### 模型窗口声明与容量估算

**已确认。** 每个实际模型配置显式声明上下文窗口及生成输出上限，不用统一 128000/4096 默认值推定任意端点能力，也不在运行时仅凭模型名猜测或自动联网更新。生成用途的输出额度独立配置；专用判断按其实际协议声明输入上限，不虚构生成参数。输出上限会影响思考/响应截断，须写明它是 Provider 生成预算，不能当作纯展示长度；映射及隐藏推理是否占额度按实际端点验证。示例配置应提供与所示模型相符的完整字段，而非要求日常手工计算每轮用量。

有适用计量规则时，按所配置模型/端点的文本分词、消息/工具表示和媒体规则估算完整请求。缺少精确规则可使用明确标记的参考估算，并预留可配置余量，初始为扣除输出预留后可用输入额度的 10%；摘要触发/目标比例均作用于最终输入预算。共享总窗口的端点可表述为 input_budget=floor((context_window-output_limit)*0.9)，若端点另有独立输入上限还要取更严格者；这不是对所有端点限制形式的假设，也不保证服务端一定接受。

图片按实际图像/分辨率及发送方式，音频按已取得的时长/格式及端点规则计量；只知道字节长度不能套用统一媒体 token 数。没有适用精确规则时可为支持的模型声明有范围限制的保守估算；连必要媒体元数据或适用估算规则都缺失时，明确报告无法完成容量预检，不按零占用放行、不自动转文字或降质。正式媒体在组装前解析与保存必要元数据，不在同步容量检查中访问网络。估算方法/版本与服务端真实 usage 分开记录；实际超窗作为明确容量失败，不偷偷丢历史后重发。

模型接入时需填写能力限额，预留余量降低可用容量，未知媒体路径可能要求先补适配；阈值须有明确分母和可追踪计量依据。10% 不是理论误差上界，规则不适用时不能靠固定余量冒充可靠支持。具体 Provider 公式、分词资源与新增重要依赖须随实际接入审阅，不以这项方向批准任意新依赖。

**委托设计。** 完整请求的容量预检放在发送前的 Engine 模型适配边界，复用同一计量服务支撑材料组装与维护。Core RequestTokenBudget 的当前编译路径超限会调用 _drop_oldest_complete_turn，因此不直接启用该裁剪策略；保持 Core 工具循环，超限由 Engine 报告/维护，不修改 Core 公共接口或复制循环。

**委托设计：计量适配的实现边界。** Engine 的计量入口接收完整逻辑请求、所选模型计量配置和已取得的媒体元数据，返回估算值、方法版本、适用范围及缺失原因；不访问网络或发起模型请求。文本分词可以复用已安装、明确指定的本地资源，消息和工具表示开销按对应路径计入；媒体按尺寸/时长规则处理，不把 base64 文本长度当作媒体 token。初次加载分词资源必须在装配期明确完成，不能在实时请求检查中隐式下载。

LiteLLM 通用 token_counter 不作为 Engine 的无条件容量裁决者：已检查的 1.104.2 路径会为图片 URL 获取尺寸，未知模型可能回退 cl100k_base，部分内容失败可返回调用方给定默认值。只复用经过适用性核对的纯计量部分，不用默认图片尺寸、未标记的通用分词或统一常量掩盖未知。OpenAI 兼容路径仅说明调用格式，不证明实际模型的分词、图片或音频计量方式；网关模型别名与计量配置分别记录。已有 10% 余量仍只是预留，不替代规则适用性验证。

### 笔记外部编辑与修改冲突

**已确认。** Markdown 文件可由外部编辑器维护。下一次模型请求组装技能目录时检查文件变化，形成该次请求的版本快照；不打断已发送的模型请求，不因文件保存自动唤醒或执行技能。此规则只适用于笔记内容，不引入主配置或插件热加载。正文读取取得当时的内容版本并保存阅读证据；目录与正文之间发生变化时明确新版本，不伪称同一快照。

覆盖、删除和移动已有笔记时携带所依据的版本；新建要求目标不存在。发现版本已变则拒绝该次修改并返回冲突，主脑重新读取后决定如何修改，不自动合并或强制覆盖，不要求人工批准。版本可由正文读取或先前成功写入取得；目录操作的目标不存在、根目录和非空删除等约束保留；参数约定见第 9 节。

代价是新增模型可见版本参数及冲突后重读；收益是防止基于旧内容的常规覆盖。内部串行提交与临时文件替换属于委托设计，但不能声称它们与任意外部编辑器构成原子版本比较：编辑器若恰好在最终核验与替换之间写入，仍存在竞争。首版不建设协作编辑系统或独占全部文件的编辑器；严格避免同时写同一文件仍需错开编辑。已保存阅读证据不等于已备份每次未观察到的外部修改。

扫描遇到不可读/非法编码/超限文件，应明确其路径和目录不完整状态，不把旧内容冒充最新，亦不把单篇坏文件变成主体整体故障。检测稳定读取及扫描资源限制需要第二阶段验证；不预先引入文件监听依赖。

### 大工具结果与有限来源覆盖

**已确认。** 对明确的长文/列表读取能力提供分段或分页：首次取得材料形成带来源/时刻/版本的读取快照，返回当前范围、是否还有后续、续读标识和原文定位；后续读取同一快照，不把变化页面的第二段拼到旧第一段。模型决定是否继续，不自动把所有页塞进当前上下文。完整性只针对已取得的文本/数据快照，不宣称包含页面所有动态内容或整个网站。

保存用于分段的原始读取结果及提取方式，已交付片段可追溯；不默认存整站镜像。原始取得/保存超过资源上限时明确失败，不先裁断再宣称完整。分段适用于工具明确请求的读取边界，不自动切分人类发言、改写图片为说明文字，或用摘要替代必须展开的原文。若本轮必须同时使用的材料仍装不下，继续明确报告容量不足。

单次写操作、控制确认和真实回执不能被通用分页器拆成“稍后再说是否成功”；是否已产生效果及关键回执身份始终直接可见。只有较大附属正文/列表按阅读契约继续获取。阅读快照不充当当前浏览器交互 ref，页面变化后不能用旧快照偷偷操作新页面。

QQ 历史保留有限缓存读取，但把预期平台读取失败、source=cache、已知消息范围/时间与覆盖未知分别返回。没有缓存时不能把平台故障表述为“没有聊天记录”；内部解析或程序异常不一概吞掉转缓存。不伪造平台支持的续读能力、总条数或缺失范围，平台未提供的信息保持未知。

这会增加模型可见的读取范围与续读参数，主脑可能需要多次读取；用于避免长文只能整份失败或反复读取前缀。已确认的续读接口及默认段长见第 9 节。

### 快照续读入口与证据覆盖范围

**已确认。** 浏览器、QQ 历史等读取仍从原能力入口取得材料；返回原有内容字段及来源信息，并补充快照原文引用、当前片段范围和宿主生成的 next_cursor。同一能力带 cursor 续读时只读取已保存的同一份快照，不重新访问外部来源。首轮获取与后续续读的参数组合必须明确，cursor 不能与另一会话/来源选项混用；需要刷新则明确开始一次新读取。字段与参数组合见第 9 节已确认接口包。

各能力共用宿主的不可变快照存储与范围读取，不在插件内重复保存分页缓存。原入口保留续读，是为了让受限 Python 可以在同一行动内逐段处理返回值；不强迫脚本每读下一段就退出并占用新的主脑轮次。read_evidence(id, level) 保留为主脑/反思展开已有原文的通用工具，并支持同一范围/续读契约；它不代替业务工具获取新的网页或平台数据，也不成为另一套外部网络入口。

分别表达已取得快照的范围和当前已经呈现的范围。QQ 快照读完不证明平台整个会话历史已读完；网页快照读完不证明动态页面全部内容已取得。返回的可引用片段身份由宿主关联原文与范围，模型不用手造来源坐标。summary/overview 仍不是原文阅读证明。

认识修订可引用实际呈现的相关原文片段，不要求为一个局部事实先读完整本材料；未读部分保持覆盖缺口，不能把读过第一页记成整份来源已复核。宿主验证片段存在、版本/范围及实际交付关系，不声称由此证明模型理解正确或结论真实。Worker 取得片段但未把原文交给模型时，也不能冒充主脑读过原文；模型收到脚本计算结果时保留其派生来源及实际交付范围。

流程：浏览器 read 取得页面快照并交付首段；Python 可继续使用同一路径和 cursor，或主脑后来用 read_evidence 展开原文引用；反思只把真正呈现过的片段纳入来源资格，尚未覆盖的内容仍明确未读。分页次数消耗既有行动调用/模型轮次预算，不自动读完全部页面，也不扩大已确认的窗口容量。

### 认识与反思

**已确认。** 默认检索当前有效认识；到期/明确被替代的旧认识退出当前使用，但原文和版本保留。未决冲突保留双方来源，不按新旧时间自动裁决。反思的每次认识修订或监管意见提交即生效，批次后续失败不撤销；批次复核完成另记。

**委托设计。** 一次认识修订原子包含新版本、来源、明确替代时旧认识退役、关系和索引待更新记录，以及本次整合回执。校验 base_version 与实际已读且仍有效来源；不等待索引更新才应用有效性。检索在排名前/返回时核对当前版本和来源状态，显式历史查询保留版本、时间及失效原因。向量是可重建派生数据，不成为权威。

监管意见保存来源、有效期、可选活动版本，交付前复查失效条件。前台可接受、部分接受或拒绝并说明原因；同意不证明事实正确。反思不持有世界行动工具，urgent 只请求重新思考；不因新增反馈重复构造无新事实的循环。

### 反思批次完成协议

**已确认。** 将批次完成从“解析最终回复里的专用 JSON”改为一次明确的结构化工具提交，暂名 finish_reflection。该工具绑定宿主当前反思批次，不要求模型复述 batch_id；用于提交复核结论、暂缓及理由、知识处理选择和程序异常判断，不执行世界行动。旧 complete_review 的一般结论登记并入该完成工具，不保留两个登记入口。

保留必要业务校验：本批分配的每个材料/片段范围都有复核或暂缓结果，两者不得冲突；每项复核说明认识已通过工具写入、无需改变或仍需等待及其理由；程序明确列出的异常有影响说明或未决判断；引用必须存在、适用且确实呈现过。宿主不通过这些结构检查宣称模型理解正确，也不要求把所有闲聊写成长时认识。

本批成功修订的 ID、版本和来源关联由宿主从真实工具回执取得，不要求模型在结束正文中再手抄回执清单。声称已写入却无对应真实有效修订时拒绝完成；已经存在但本批未修改的认识不能伪报为新写入。一次修订可能只涉及材料的一部分，宿主不能因为某来源被引用过就自动将整份来源标为已复核。模型仍须表达知识处理取舍，宿主负责已发生事实及覆盖记账。

完成工具成功提交后，本批完成事实与已提交认识独立于最后自然语言收尾；随后模型超时或会话提交失败，不撤销该完成事实、不重做修订或重投同批已完成来源。会话失败仍保留必要经历与真实回执。完成之后禁止再修改该批处理结果；重复确认返回已有完成记录，不能借重试覆盖结论。未成功完成工具调用时，普通最终文字或一句“完成了”不确认待复核来源。

参数/覆盖错误通过已有工具错误机制在本批剩余预算内纠正；存储或内部故障按真实故障处理，不伪装为模型参数错。完成工具及 Core 正常结束会话所需的后续请求都计入既定轮次/时间，不改 Core 的提交机制，不额外赠送收尾轮次。该方案可能比一次正确的最终 JSON 多一次模型收尾请求，但统一使用已有工具 schema/校验路径，取消另一次最终正文解析及专门补写 JSON 流程。

### 反思工具清单

**已确认。** 反思的模型工具收敛为以下职责，不改变主脑已保留的世界行动入口：

| 工具 | 职责 |
| --- | --- |
| recall | 检索当前有效认识或明确查询历史认识 |
| read_evidence | 按已确认范围契约展开原文、真实请求/回执与归档材料 |
| revise_memory | 逐次提交有据认识修订，立即产生真实回执 |
| supervise | 逐次提交面向主脑的监管意见，立即生效 |
| finish_reflection | 集中提交本批复核结论、知识处理取舍、暂缓与异常判断，确认覆盖 |

移除反思可调用的 review_context 和 propose_compression：实际请求及归档经 read_evidence 定位/展开，容量维护由宿主按阈值发起无工具计算，模型不再另开手动替换会话摘要的路径。应先保证新原文入口确实可访问原工具承担的历史材料，而非删入口后失去复核能力；源版本、失效及完整性检查继续保留。

单项复核结论在 finish_reflection 成功时统一确认，途中生成但未提交的结论只保留过程证据，不伪报正式完成。revise_memory/supervise 已成功提交的认识和意见仍立即保留，不随最后完成失败而撤销。完成工具允许按主题合并多项来源，不要求为每条聊天单独写总结。工具参数与返回字段见第 9 节已确认接口包。

### 反思触发与合批节奏

**已确认。** 普通新增经历按批反思：从最早尚未安排的新材料起等待最多 60 秒，或自上次反思取批后累计 8 个已完成前台交互轮次，先满足者安排下一批；两个阈值可配置。这是请求调度时机，不保证模型在 60 秒内完成。后续普通输入不能反复重置最早到期时间；无新增待处理材料、无新到期依据时不周期调用反思模型。

明确的行动失败/部分效果/未知结果、活动完成/失败/需要决策，以及前台最终失败可优先安排复核。这些原因由宿主已确认的结果类别产生，不从任意输入正文的 status 字样推导。反思已有批次运行时只登记待处理事实，优先进入下一批，不并发推进同一会话、不为每条事件开一个反思任务。

移除单凭文字以“纠正/更正”开头就立即反思的规则，也不因 VAD 或其他 urgent 调度信号本身立即反思。语言纠正仍完整进入主脑及随后反思，主脑可在当前交互立即理解和行动；长期认识的反思更新通常等待上述合批时机。立即抢占生成和立即更新认识是不同需求，不为区分它们再增加一层模型分类器。该调整可能延后普通语言纠正进入长期认识，换取减少无实质新结果时的后台调用。

上下文摘要按已确认容量阈值独立安排，不等普通反思的合批时间，尤其在必要请求已超限时先完成有效容量维护；达到预警而尚能容纳请求时仍可继续。摘要可以借用同一模型配置，但不因此推进反思会话或自动启动一批语义反思。来源冻结、版本核验与空闲安装约束保持。

一批结束后仍有未纳入处理的新材料，可有界安排后续批次；已明确暂缓、同一失败或没有新增证据的事项不能靠定时器不断重跑。反思自身生成的文字、摘要安装和前台对监管的单纯同意不自行形成循环触发。临时模型故障仅使用已确认的单请求重试；同批结果格式纠错共享既定 8 次/600 秒预算，不通过再次调用 session.run 重置额度。已成功提交的认识/通知保留，失败不抹去它们，也不引入人工恢复队列。

### 活动生命周期

**已确认。** 主脑委托局部目标，插件驱动执行专业流程；通用活动不依赖旧尖塔。暂停/结束先受理并立即禁止新步骤，实际收尾后异步确认，UI/主脑区分正在暂停与已暂停。宿主统一提交控制状态，驱动只报告事实。

- 同命令身份重复投递返回已有结果，不重复调驱动。迟到暂停不覆盖 completed，旧恢复确认不复活 ended。
- 重启把未结束活动的中断交主脑核对，由它决定恢复或结束；不自动重放或启动驱动。
- 预算按实际 running 时段累计，包含等待模型/设备；paused 和宿主未运行不扣减，恢复沿用余额。耗尽禁止新步骤并反馈，不自动续期。

**已确认的控制接口方向。** 保留 me.activity 路径及 command 的 start/pause/resume/end/adjust 语义，追加额度使用下文 extend。start 只需提供已登记 definition 和 goal，activity_id 由宿主生成并在受理回执中返回；后续控制引用该 activity_id，adjust 再提供新 goal。command_id 不再是模型填写的参数，由宿主从可信能力调用身份分配/关联，仍保存在控制记录与回执中供查询。精确参数有效组合在边界校验，不让无效组合悄悄被忽略。

创建活动记录、分配 activity_id 和持久化命令接管在启动驱动前完成。返回结果明确区分受理状态与活动实际状态，不因生成了 ID 就宣称已经运行。活动概况/后续确认继续携带相同 activity_id；主脑从返回值、当前活动材料或真实回执取得引用，不要求靠历史自然语言猜目标。

同一已接管命令的内部重投/查询返回原有记录，不再次创建活动或调用驱动；UI 重传用既定稳定请求身份找到同一宿主命令，不因服务端重新生成 ID 而重复执行。模型在之后主动发出一次新的 start 是新请求，不按目标文本相同自动合并；若先前结果未知，应先核对现有活动与回执，不能把再次 start 伪装为查询。活动定义的单实例约束及全局数量/预算限制仍生效。去重标识归宿主，目标、控制种类和局部目标的选择仍归主脑。

**委托设计。** 命令、确认、反馈与生命周期携带 activity_id、command_id、run_generation 和版本。提交时读取当前版本，独立保存控制状态与业务结果；等待驱动在事务外。普通进度可更新概况，关键反馈可靠交给前台/反思，原始反馈保留。恢复端口先提供实际状态核对材料，无法确定保留未知，不通过重做旧写操作猜结果。

**已确认的计时精度。** 活动预算是运行约束，不作为精确计费账本。运行期间使用单调时钟累计，持久化检查点目标间隔初始为 5 秒；正常退出运行计时状态时结清累计时长，正常关闭尽力提交最后累计值。仅在实际运行期间安排周期提交，不每秒唤醒所有暂停活动。计时提交失败遵循权威存储故障规则，不继续无记录地派发新步骤。

异常终止后，以最后成功持久化的累计时长计算剩余预算；未记录的末段不推算、不预扣完整检查点间隔，不以重启时间减去最后记录时间而误扣离线时长。恢复材料明确给出已记录用量、最后记录时刻和末段计时不完整。运行时可已观察到更多时长，但崩溃后不能把未持久化值当成仍可取回。

这允许异常终止少计最后一段；5 秒是正常调度下的提交目标，不是对事件循环卡顿、系统冻结或提交延迟的硬误差上界。不做跨崩溃精确时钟服务。周期累计值通过同一活动版本/运行代次提交，避免重复累计、迟到检查点覆盖暂停结算；正常运行的预算截止检查使用当前累计量，不等下一次落盘才停止派发。重启仍由主脑核对后决定是否恢复，余额不因重启重置。

**已确认的额度授予。** 每项活动初始授予 60 分钟实际运行额度，可配置；任何一次授予/追加后的剩余额度不得超过配置上限，初始上限同为 60 分钟。暂停及宿主离线不扣减，累计已用时长不清零。预算耗尽后仍按已确认规则禁止新步骤、等待在途收尾并将进展/结果交主脑核对，不自动结束目标或补满额度。

主脑可基于实际进展明确追加额度，保留同一 activity_id、目标、工作检查点及原回执链，不要求结束旧活动再创建替代活动。me.activity 增加明确的 extend 命令，携带追加时长与继续理由；宿主校验正值、余额上限、状态与命令身份，并记录授予事实。仅允许已停止派发、没有宿主在途收尾的暂停/预算耗尽/重启待核对活动追加；已完成或已结束活动不能借此复活。重启后的追加只改余额，未知外部效果仍保留，恢复前的主脑核对要求不因追加而解除。

追加只改变余额，不启动驱动；主脑还须显式 resume，沿用两阶段控制和恢复校验。驱动不能自行续期，WebUI 普通恢复不追加余额，配置的行动/模型资源上限也不会随活动加时改变。同一追加命令重投只记一次额度，不因重试重复增加。

不另设活动整个生命周期的累计时长上限：长目标可经过多次主脑明确核对继续，每次最多获得配置范围内的未来运行额度。活动可能长期持续，因此预算是定期重新判断的边界而非绝对寿命上限；不能把驱动自动续租包装为主脑判断。start/extend 参数组合见第 9 节已确认接口包。

## 6. 执行、插件与原子存储

### 行动与插件接口

**已确认。** 主脑用受限 Python 短段组合能力，允许结果复用、条件、异常处理与受控并行；不持久化局部变量、不用无限脚本代替活动。不另增重复的世界行动工具入口，不自建 JSON 编程语言。

**委托设计。** 插件提供纯声明的配置类型、依赖、对象/能力挂载及必要活动定义；app 校验后创建资源所有者，再启动接入。插件登记清理，关闭先阻止新工作、再收尾、逆序释放。就绪/离线是明确状态，未启用插件不构造。业务命令直接调用负责组件，不靠事件订阅做必需步骤。第三方插件不取得主脑可变会话或 Worker 真实对象；自有文件/状态按实际业务契约接入，不建设通用 ORM 或全局服务定位单例。

**已确认的启动边界。** 配置/依赖/路径冲突、目录锁或权威库不可用时启动失败并回收已取得资源；已正确装配的可选服务暂时离线时，报告原因并允许无关功能运行。内部程序错误不能一概包装为离线。启动顺序为纯配置/声明检查、实例锁与核心存储、主体和插件资源装配、可靠接收入口就绪、按已启用方式启动连接。创建资源后立即登记清理，失败不留下后台任务；主脑不自动回退成离线回声模型。连接恢复不重发未知效果，也不自动恢复活动；各协议的有限重连规则仍须核对。

宿主结构化单次调用如确有使用需求，可直接走共享执行服务，不先生成 Python；新入口按真实调用需求收敛，旧 Runtime 公开 API 不兼容。执行服务保存冻结路径、目标、参数及调用身份，检查实际参数与并发约束。

### QQ 连接恢复

**已确认。** 保留 reverse/direct 两种已存在连接方式。reverse 由 Engine 维持监听，断线后等待外部 QQ 端再次接入，不能伪造由 Engine 主动发起的重连；监听失败属于真实服务故障。direct 由 Engine 负责有限恢复：初始每轮最多 5 次连接尝试，每次最长 10 秒，失败后依次等待 1/2/4/8 秒；数值可配置。成功连接持续稳定 60 秒后才重置这一轮的尝试预算，短暂连接即断开不反复获得全新次数。

只有可识别的网络/服务暂时不可用进入自动恢复；已知凭据拒绝、配置或协议错误明确停止，不把内部异常循环包装成网络故障。主动模式启动时服务离线也采用相同恢复规则，不阻止已经正确装配的无关能力运行。恢复耗尽后保持可观察离线状态，主脑或 WebUI 可明确发起新一轮连接恢复；提供对应模型连接控制入口与面板“重新连接 QQ”操作，精确路径见第 9 节已确认接口包。reverse 的操作只查询/恢复自身监听，正常等待外部连入时说明其状态，不假装主动连上 QQ。配置内容变更仍须重启，不借重连实现热加载。

连接恢复只恢复传输，不重发旧 API 调用、不重放未知发送，也不把新连接建立当成旧消息已经送达的证明。旧连接的请求由原连接代次和 echo 关联；断线窗口按实际发送阶段保存未开始/未知/已确认结果。断线期间未接管消息的缺口保持可见，不宣称外部平台必然补投。缓存历史仍按已确认有限来源规则返回。

只保留一个连接恢复任务，重复恢复请求合并/返回当前状态，关闭后不继续尝试。输入过载造成断线时先等待接管容量恢复，不立刻连接再过载；容量不可用与网络失败分别呈现。关键离线、恢复耗尽和连接恢复状态可交主体，重试中间步骤更新状态/诊断，不逐次制造反思唤起。凭据与接入协议验证不属于人员权限等级，不因移除 OWNER/GUEST 而删除。

短时故障自动恢复，持续故障需要一次明确恢复决定；主脑可以发起该决定，不要求建立人工恢复队列。反向监听继续等待外部接入，不受主动重连次数耗尽影响。本项只定义 QQ 连接，不将同一循环套到收音、播放、浏览器点击或其他有副作用的操作上。

### QQ/QZone 返回结果与原文边界

**委托设计：落实已确认的真实回执与材料覆盖规则。** 适配层分别保存请求意图、所收到的响应及按具体动作契约解释的结果，不把所有 None/空对象当成失败，也不把缺少状态字段的任意对象当成成功。动作允许 data=null 时，完整的成功信封可作为平台确认依据；需要返回标识或实际值的动作缺少相应字段时，标明该部分未知，不用请求参数补成“实际值”，也不因此抹去已收到的平台成功声明。发布后无 tid、评论后无 comment_id 与确定未发布/未评论不是同一结果。

结果记录区分平台报告与独立观察；正常符合约定的成功响应不要求再发一次网络查询才认可，也不声称对端已阅读或效果永远维持。只有受理或语义不完整的响应不能冒充完成。发送前明确拒绝、发送后断线/超时、已收到平台拒绝和已收到平台成功分别保留；写入未知结果不自动重发或试探另一组参数。风控/权限等平台错误保留原动作和返回码，不借恢复连接自动重做。适配器兼容的缺省字段必须有具体协议/版本依据，不能保留通用“缺字段算成功”的回退。

QZone 列表/动态可以保留用途明确的短卡片，但取得的原始响应先保存为快照，卡片明确为 overview，并关联可展开正文/片段；图片链接不是已经看过像素。无法投影的条目保留位置与原因，不能静默跳过后声称全页已完整解析。保存响应只证明已取得这一页，不证明远端全部历史或完整媒体已取得。远端 pos/page_num 分页与读取已保存快照的 cursor 是不同操作，不能用本地续读冒充远端深翻页已实现。具体新增模型可见返回字段按已有公共证据/覆盖契约组织，若需要新增模型调用入口或参数，再集中列入接口包，不暗中修改语义未变的调用路径。

该基准下，保留 qzone_feeds(page_num=1, count=10) 的路径与参数；首版 page_num>1 明确返回不支持，不向平台发送已知不可靠的深页请求。首页的 has_more 只说明远端可能还有内容，不能据此承诺本适配器可以继续读取。qzone_list 的 pos/num 列表分页是另一端点，不一并禁止。qzone_unlike 仍在已确认保留范围内，按现有参数发起明确调用并保存真实结果，不因文档未核实而删除，也不通过重复点赞/其他写操作模拟取消；真实效果列为尚未验收，不能用内存客户端通过替代验证。

### Windows Worker

**已确认。** 默认每次行动独立 Windows 子进程，保留 CodeExecutor 替换接口，首版不建设容器/WASM。模型代码不在宿主 exec；保留语法/导入/反射约束。通信为解析前有大小上限的数据协议，核验种类、序号及行动身份。硬资源限制不可静默跳过；子进程加 AST 不宣称能安全承载任意恶意程序。

**委托设计。** 采用专用数据连接传递有界 JSON 帧；不使用子进程可任意构造的 Python 对象反序列化作为宿主接收边界。默认只允许本次 Worker，绑定握手与行动；未知/重复消息终止相应行动。持续设备进程和短期 Worker 保持不同生命周期。

Windows 原生 Job Object 可管理并终止关联进程，设置 KILL_ON_JOB_CLOSE 后可在最后句柄关闭时终止关联进程；扩展限制提供提交内存上限，基本限制提供进程 CPU 时间等约束。选择标准库 ctypes 封装有限调用作为首选设计，不新增重要依赖；先建立限制及归属，确认成功后才放行模型代码。墙钟期限由宿主持有，不能与 CPU 时间混淆；Job Object 也不提供完整文件/网络隔离。嵌套 Job、分配失败、句柄继承及父进程异常退出必须验证，不在验证前声称保证成立。依据：[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)、[扩展限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_extended_limit_information)、[基本限制](https://learn.microsoft.com/en-us/windows/win32/api/winnt/ns-winnt-jobobject_basic_limit_information)。

### 行动资源预算

**已确认。** 单次脚本的执行/派发期限初始 180 秒，包含 Worker 启动、脚本执行和等待宿主能力；CPU 时间初始 15 秒、Worker 提交内存初始 512 MiB。其余初值沿用现有数量级：最多 64 次宿主能力调用，源码 64 KiB，stdout/stderr 合计 64 KiB，最终 JSON 结果 1 MiB。均通过宿主配置，模型不能在脚本或能力参数中自行抬高；正常能力的独立超时仍生效，不因行动额度更长而自动延长每个网络请求。

墙钟等待与 CPU 消耗独立累计：网络/音频等待会消耗 180 秒期限，但通常不消耗多少 Worker CPU；CPU/内存仅限制 Worker，不把整个宿主、浏览器和音频服务算入此数值。Windows 内存指标采用已选 Job Object 的提交内存口径，不写成 RSS。参数是待实机验证初值，旧 Windows 路径静默跳过 CPU/内存限制的事实不能用来证明这些值已适用新 Worker。

超时、CPU/内存超限或 Worker 协议故障时，撤销该行动的后续派发资格并终止相应 Worker；排队但尚未进入 Provider 的请求不能随后启动。已经进入 Provider 的调用由宿主按各自有限期限与资源规则收尾，保留成功/部分效果/未知回执，不因 Worker 消失就标记未发生。180 秒是脚本与新步骤的期限，不保证所有在途外部工作此刻物理停止，也不把收尾时段作为继续执行脚本的机会。迟到回执继续归属原行动，Worker 不复活，不重跑脚本。

调用次数达到上限后拒绝下一次调用，仍允许脚本在其余预算内整理已取得结果；输出/结果过大明确报告，不悄悄截断成看似完整的成功结果。大正文按既定分段能力取得，媒体用引用交接，真实能力回执独立持久化，不受 Worker 最终 JSON 失败抹除。长时间专业流程归活动，不通过反复延长短脚本绕过生命周期。Worker 中间消息与帧限额见下节已确认约定。

### Worker 中间消息大小

**已确认。** 除已确认的脚本最终 JSON 结果上限，单次能力调用的参数 JSON、宿主向 Worker 交付的单次结果 JSON 各以 1 MiB 为可配置初值。大小按紧凑 UTF-8 JSON 的实际编码字节计量，不用字符数或引用指向的媒体大小代替。协议单帧初值 2 MiB、可配置，包含消息类型、调用身份和状态等信封；装配时检查它足以承载其他已声明的单条有效载荷及信封，不允许配置组合导致已允许的结果必然无法发送。

Worker 发送前检查，宿主仍在分配完整消息/JSON 解码及创建能力任务之前核验长度和调用预算。合法消息的参数超限在外部动作开始前明确拒绝；伪造长度、超大帧或非法协议按既定 Worker 协议故障终止该行动，保留此前真实效果。宿主回传结果超限时，按已确认规则保留原始结果/实际效果，返回明确的交付容量错误及证据引用，不截正文、不重做调用、不把已成功写入改成未发生。

原始媒体仍在宿主权威存储，Worker 接收引用。大读结果按已确认快照/片段读取；该限额并不把正式媒体或整份原文限制成 1 MiB。启动目录来自宿主已核验声明，可按有界帧分段交付，接收端按本次冻结目录的明确总长度/版本核验完整性；这不改变模型每次看到完整能力目录的约定，也不增设“只给 Worker 一部分能力”的行为。

代价是旧短脚本可构造并发送的超大中间对象会被拒绝，需要分页或引用。已有最终结果上限与 Worker 内存限制不能替代此限制，因为接收端在检查最终结果之前就已承担中间对象的解码和调度成本。

### 全局执行并发及外部输入积压

**已确认。** 一个宿主采用以下可配置初值。这些是接管/资源上限，不是模型一次必须阅读的材料量，也不是对整库历史的保留配额。

| 项目 | 初值与计量范围 |
| --- | --- |
| 同时运行的行动 Worker | 4 个，持续设备进程不计入 |
| 同时进入 Provider 的普通短调用 | 16 个，仍受目标串行等更严格约束 |
| 未结束活动 | 8 个，包含暂停/待核对活动，避免通过暂停无限创建；终态历史不占名额 |
| 未完成接管后处理的外部输入 | 1024 条，以及 256 MiB 逻辑负载；任一上限达到则停止继续接管 |

外部输入额度覆盖已接管而尚未完成注意/前台处置的输入；observe 等明确处置后退出此积压计量，不要求外部回复才算处理。字节包含输入原文和实际接管的媒体内容，不能只算引用字符串；同一媒体被不同输入引用时按各输入逻辑负载保守计量，不等同于 SQLite 去重后的磁盘占用，也不要求将这些字节常驻内存。历史存储、反思待复核来源与诊断仍各按既定持久化/流量规则，不能将此额度误称为整个系统所有队列均已受限；内部队列责任见下文，不将数据库长期保留误当作无界内存排队。

Worker/普通调用的等待队列必须有界，入队时取得绝对截止时间；等待占用该行动/调用已有时间预算，逾期撤销后不能在资源空闲时突然启动。Worker 已终止但 Provider 仍在收尾时，相关调用名额保留到实际结束，不能提前释放名额掩盖在途数。按来源轮转安排普通等待，避免一个活动反复占满；同一来源保留明确次序，不通过取消已开始副作用给新任务腾位置。主脑和反思仍各自串行推进会话，注意判断以有限工作任务合批，不为每条输入创建无限等待任务。

停止收音/播放、暂停/结束活动、关闭及关键回执提交使用独立的有界控制/收尾通道；其类别由宿主登记，模型不能自称控制请求绕过普通限额。设备的持续收音/采集生命周期不长期占用普通短调用名额，其启动/关闭仍由实际设备所有者约束。控制通道不被普通排队占满，但仍可能因设备/存储真实故障无法完成，界面必须如实展示。

外部输入额度耗尽时遵循已确认的减速/暂停/明确拒收规则；不挤掉已接管聊天，不伪报已接管。内部真实回执不能因为外部输入额度已满而丢失。支持等待的接入方可等容量，不支持的平台明确记录未接管缺口；QQ 传输继续区分 echo 回包与业务事件，不能用阻塞回包换取假可靠。这里不增加 OWNER/GUEST 或发言人优先等级。初值未经过负载验证，允许依据第二阶段有代表性的并发场景调整后审阅。

### 内部队列、任务与背压责任

**委托设计。** 可靠待办和执行中工作分开：数据库记录尚未处理的事实，内存只保留有界执行者、身份引用和当前正在交接的载荷。不得以“已有外部输入限额”代替下表中的任务/队列约束；禁止每条数据库待办都创建一个等待中的 asyncio.Task。

| 通路及所有者 | 有界方式与饱和处理 |
| --- | --- |
| 插件 → 输入接管 | 宿主预留已确认的条数/逻辑字节额度后才确认接管；未能取得额度时由适配器暂停或明确拒收。QQ 回包与业务输入分开，临时候选仅按已确认范围更新 |
| 输入 → 注意 | 一个串行注意工作器按已确认批量取引用，正文/媒体到组批时加载；待处理身份留在库中，不为每项维持一个门控任务 |
| 前台、反思与摘要 | 前台和反思各自一个会话执行者；每条会话至多一项摘要维护，同版本请求合并。数据库游标分小批读取不改变最终选材，不能将存储分页冒充模型已读覆盖；没有新来源不自循环 |
| 行动 Worker | 新 Worker 先取得已确认运行名额。已接管的主体/活动所有者保存其有期限的待执行意图，等待名额不创建额外 Worker；外部调用方未接管时满额明确返回忙，不建立无限隐藏等待队列 |
| Worker → 普通能力 | 宿主在创建处理任务前核验帧、调用序号及该行动剩余调用次数；活跃 Worker 数乘每行动调用数构成这一路等待记录的上界。进入 Provider 再取得全局短调用及目标名额；过期等待删除资格，不迟启动 |
| 活动驱动 → 能力 | 同样经执行入口；每个新派发先取得名额，驱动不能在宿主登记无限未受理调用。持续设备会话由设备所有者持有，不长期占普通短调用名额 |
| 停止/关闭与实际回执 | 停止意图归目标当前生命周期操作，重复命令查询同一身份；不把无法接管的冲突控制伪报已受理。已开始调用在启动时就持有完成记录位置，结果提交前不归还所有权，因此普通等待满载不能挤掉收尾 |
| 业务提交 → 存储线程 | 已接管所有者逐项等待提交结果，不无界批量投递；队列传引用与不可变提交数据。控制/回执可先于尚未开始的普通提交，已经进入 SQLite 的事务不被中途抢占；故障按权威存储规则收尾 |
| 索引与可靠交接 | 待索引版本/待投递身份保存在库中，由固定消费者取批；同一目标的过时索引工作可失效，权威认识与原文不能删除。关键交接确认与业务提交保持原子关联 |
| 页面状态与诊断 | 页面状态是带版本的最新快照，慢页面重取而不为每次刷新积累完整副本。诊断按有限缓冲/轮转处理，丢弃或过期有计数/范围标记；不得借此丢失权威回执或把缺口展示为完整 |

具体容器大小由这些已确认名额、声明的消息上限和同时存在的所有者数推导并在实现中明确，不另外创造一组可绕过产品额度的默认队列。新增接入或长期后台任务必须说明其所有者、同时在途上界、拒收/等待期限与关闭顺序。库中长期待复核记录不常驻内存，其保留仍受第 7 节约定；它不等于后台模型可以无限自动重试。性能瓶颈必须通过代表性负载验证，不以增大多个队列掩盖消费者停滞。

### 状态与事务

**已确认。** SQLite 为权威库，正式媒体用同库 BLOB 内容去重，原文/请求/检查点引用媒体。相同字节不等于同一次经历，来源和发生身份仍分别保存。Notebook、声线预设、导出音频等保持独立文件用途。一个权威数据目录只运行一个宿主，先取得实例锁再打开接入；不依赖陈旧 PID 文件判断是否占用。

**委托设计。** 存储服务拥有一个专属数据库工作线程和连接，串行执行有限队列中的短事务；业务调度在事件循环上，数据线程不调用模型、插件或异步回调。原因是 BLOB/提交 I/O 不应阻塞实时调度，非声称已测得性能瓶颈。只传不可变提交数据及版本，返回提交结果；取消等待不等于提交回滚，必须收回真实结果后决定下一步。关闭先停止借用者，再排空已受理写入并关闭连接。容量应为已开始调用的收尾保留通道，不能由新输入塞满队列阻断回执。

| 内部提交操作 | 同一事务的内容 |
| --- | --- |
| admit_input | 来源去重身份、原文、BLOB/引用、待注意状态 |
| commit_attention | 判定证据、输入状态、待处理/延后记录 |
| record_call_result | 单次调用的确认/未知结果、实际回执、关键交接 |
| finish_turn | 输入处理结果、成功检查点或失败经历关联、必要邮箱确认 |
| finish_reflection | 当前批次/版本核验、已读片段覆盖、复核结论与暂缓、实际修订关联、批次完成和必要邮箱确认；不重新执行此前已成功的知识修订 |
| revise_knowledge | 新版本、来源/替代/有效性、整合回执、索引更新 |
| apply_activity_transition | 命令/运行版本核对、控制状态、确认与关键反馈 |
| fire_alarm | 单次消耗或每日推进、原定时间及待投记录 |
| install_summary | 原历史归档、来源与版本、候选检查点和摘要关联 |

接口名称为内部设计，不直接作为模型工具。不会机械建每表一个 Repository。SQL/JSON 结构用明确类型解码；未知格式拒绝，不静默删字段或用空库替代损坏库。不需要旧 Runtime 迁移，Engine 格式与支持的 SDK 编码组合仍需明确版本。

**委托设计：权威记录边界。** 以下划分表达所有权与关联，不要求每行建立一个服务类，也不是最终 SQL 表清单。

| 记录组 | 保存的事实与关联 |
| --- | --- |
| 原文与媒体 | 原始输入/取得的材料、不可变快照、来源与取得时间、媒体引用；片段记录范围及实际交付对象，不把保存等同于模型读过 |
| 输入与交接 | 原生去重身份、接管状态、注意结果、延后条件、必须投递的待办；完成交接与相关业务提交原子发生 |
| 模型与会话 | turn/request/attempt、实际请求顺序与材料引用、可取得的响应、失败/用量、检查点及摘要版本；配置快照脱敏，不保存凭据 |
| 行动与控制 | action/call、派发意图、实际开始与真实结果、控制命令/确认、播放事实；会话失败不能回滚这些记录 |
| 活动 | definition、目标、当前状态/版本/运行代次、已授予与累计用量、驱动检查点及中断核对信息；宿主状态和驱动业务结果分列 |
| 认识与反思 | 认识版本、有效性、替代/冲突与来源片段，反思批次/覆盖/暂缓/真实修订关联；索引只作可重建查询辅助 |
| 时间与休息 | 闹铃定义、下一次到期/消耗身份、明确休息状态及必要交接；调度内存不能成为唯一存续依据 |

业务记录携带因果身份，不能只用一份无结构日志推导恢复状态。诊断过期不会删除上述权威事实；当前状态查询可维护投影，但投影不得成为另一份可独立修改的权威记录。不搭建通用事件溯源重放框架。Notebook 的当前文件仍由文件系统拥有；读取所得快照用于追溯，不能反向当成当前文件正文覆盖外部编辑。

调用开始前先持久化调度意图，在实际进入 Provider 前再次核对生成/活动/关闭状态。持久化“准备派发”不证明外部操作已发生；此窗口崩溃按可确认记录保留未知或未开始，不伪报成功。能力并发锁内核对最终启动条件，数据库等待后也不能采用过期状态。真实调用一旦开始由执行服务持有，回执独立于 Core 整轮提交。

### 交接、关闭与故障

**已确认。** 必需步骤显式调用；不能丢的交接与状态同事务入账；事后通知各自失败，不改变已完成能力结果、不阻断无关消费者。可靠交接按身份确认，确认表示接管责任而非模型已完成思考。不承诺全局恰好一次，不给日志/动画全部建立持久队列。

QQ 等外部发送超时不能靠重新发送确认结果。现有 OneBot echo 是回包关联，不是服务端幂等保证；Engine 保留发送前、发送后未确认和明确回执的区别。不将本地重复调用缓存宣传为平台恰好一次。

关闭后禁止下一项能力调用，仅给已进入 Provider 的调用有限收尾机会；保存真实/未知结果后按依赖释放。不可取消的宿主线程不能靠杀 Worker 撤销；收尾超时报告关闭未完成，不提前释放其借用资源。

**已确认的关闭期限。** 正常关闭从宿主接管退出请求起，初始共等待 30 秒、可配置；该期限覆盖各层停止、在途收尾、权威提交与资源释放，不是每层重新取得 30 秒。立即停止新接收确认、新模型请求、连接恢复及下一项能力调用；停止现场音频/候播与设备采集，活动停止新步骤。已开始调用保留真实结果或未确认状态，按依赖释放。

期限内全部完成才报告正常关闭成功。超过期限时显示“关闭未完成”及仍占用资源的工作，保留关闭任务、服务/存储引用和必要查询能力；不恢复正常业务、不提前释放借用资源、不自动强退。后续在途实际结束时继续完成清理；再次等待同一关闭过程不重新启动清理或重置其原期限。这里的 30 秒是正常等待/报告期限，不保证无法取消的线程在该时刻物理结束。

独立 CLI 第一次 Ctrl+C 请求正常关闭，并显示再次 Ctrl+C 将强制退出的说明；第二次 Ctrl+C 表示明确强制退出，可在等待期间或超时后使用。强制退出以非零退出码结束本 Engine 进程，只处置能确认归属的子进程，不终止外部 QQ 服务或用户自行启动的浏览器。强退不能依赖一次额外数据库写入成功才能执行；未提交的内存回执可能丢失，外部效果仍可能发生。下次启动依已有调度意图/回执报告中断和未知，不伪造正常关闭记录或重放行动。

进程终止由独立 CLI 入口负责。嵌入式宿主关闭接口只返回/报告未完成及实际错误，并保留可继续等待的生命周期状态，由调用方决定整个进程的处置；不从库内部结束调用者进程。主脑能力及首版 WebUI 不新增强制结束宿主入口。实际信号处理、所有者子进程清理与超时后的引用寿命在第二阶段验证，不将关闭等待取消等同于资源已经回收。

局部媒体配额只限制受影响材料；诊断存储失败不影响业务。权威提交故障停止新接收确认、模型请求和能力派发，有限收尾。故障状态无需先写坏库才生效；少量在途内存回执明确未持久化，可查看/导出但不保证进程退出后存在。修复后重启检查恢复，不切成内存主体继续服务，不自动新建空库。错误分类和预留容量仍需具体验证。

## 7. 业务持久化、语音、身体与 WebUI

**已确认。**

- 闹铃和明确休息状态跨重启保存。错过的单次提醒补投一次，带原定时间与迟到信息；每日只安排下一次，不逐条追补。休息期限到不等于自动起身或发送。
- 正式原文、真实回执和已入账媒体默认长期保留；历史摘要不删原文。临时候选/未入账 PCM 可释放，不增加全量录音。派生索引可重建。诊断/普通日志有限轮转，初始时间尺度 7 天，容量可配置；不清理权威历史冒充恢复。
- 音频模块拥有合成、设备、播放身份和真实进度；Live2D 消费同一播放事实做可选视觉。身体不可用不阻断仍可用音频；若共享进程连音频一起损坏，仍报告中断，不重播或重复合成。
- 区分已开始合成与已开始发声。新输入不自动取消已开始合成；明确停止、实际故障和关闭另按规则处理。来源只用于归因，不新增一条发言只能回复一次的限制。
- 主脑决定语义表情/姿态，本地模块做待机、平滑运动、音频重音与口型；首版不另建自动情绪模型。宿主分配身份/期限，播放结束后的迟到动作不补演，设备恢复不复活旧动作。
- 一次说话可同时提交可选身体姿态，通过现有 speak 路径增加表达参数；宿主关联同一音频，声音与身体分别报告结果。纯姿态仍可独立调用，不新增必须先创建表达句柄的步骤。字段、数值范围与默认值见第 9 节已确认接口包。
- WebUI 遵循 Design，运行状态、设备观察与快捷控制为范围；详细诊断继续终端查询/导出，主配置仍文件编辑。独立调音室保留。
- 设备由宿主持有。刷新/关闭页面不停止已开启收音和观察；重开只查询同一实例，Engine 重启不自动重开设备。旧会话/迟到请求不复活设备；断线页面标示状态过期。查询不打开设备。

**委托设计。** UI 查询返回实例身份、快照版本、当前状态和必要操作结果；命令带请求身份及适用会话/版本，服务核验后受理/确认，不直接写缓存造成假状态。同请求重传不重复启停；多个页面共享宿主事实。UI 使用本机应用接口，不部署第二个主体或直接打开 SQLite。具体 UI 路由随宿主接口收敛；必要模型工具及声音/姿态联合表达接口见第 9 节已确认接口包。

### 现场语音排队与停止范围

**已确认。** 现场语音由音频所有者维护一个顺序序列，同一时刻只执行一项合成/播放，其他已接管说话请求按宿主接管顺序等待。候播数量初始最多 4 项、可配置，不含正在合成/播放的一项；超额明确拒绝新请求，不挤掉已受理内容。等轮到该项才启动 TTS，首版不为候播项预先并行合成。等待计入既有行动/能力期限，过期项报告未开始，不在以后补播。

新 speak 默认排队，不覆盖等待内容、不自动打断当前声音。新一轮生成本身不取消已受理音频工作；停止由明确音频控制、已确认的持续人声 VAD 规则、关闭、期限或实际故障触发。来源用于归因，不恢复旧 consumed/expression 票据的一次发言只能回复一次限制。脚本需要确定语义顺序时应顺序 await；并发提交的受理顺序不能伪称模型原本有某个文字顺序。

明确的“停止语音输出”停止当前合成/播放，并取消该停止请求接管时已经排队的全部现场语音。由音频所有者先撤销这些请求的后续播放资格，再有限等待实际清理；同步合成不能物理撤销时，其迟到音频也不得发声。已播放部分、合成已发生但未播放、完全未开始分别保存真实回执。WebUI 使用“停止语音输出”，名称体现候播也被取消。

这不是永久静音：停止之后新接管的显式 speak 请求仍可发声；宿主确定停止与新接管的先后，不能靠线程完成顺序猜测。停止收音继续与停止语音输出分开，不在本项改变已确认的 VAD/生成抢占触发规则，也不自动停止无关活动。排队和当前声音的 Live2D 联动随相应播放事实取消，不在恢复连接后补演或重播。record 等只生成文件的能力不加入现场播放队列。

并行请求可能等待，满队列会显式失败；同一声音不重叠、新说话不悄悄挤掉旧说话，明确停止后也不会立即接着播放旧候播。音频队列与执行服务等待状态须有统一可观察身份，避免在多层锁后隐藏另一条不受停止约束的队列。

### 持续屏幕观察的完成确认

**已确认。** 持续观察保留一个已接管待处理画面和一个可替换的最新候选；将解除在途等待改为宿主按 input_id 确认真实处理结果，不要求主脑额外调用 me.computer.react。明确仅记录或前台正常处理完毕、没有对外行动也可结束此次等待；暂缓仍保留待处理关系，生成抢占不凭空确认未处理输入。取得/模型/容量失败应明确显示并暂停继续投递，保留原文和真实错误，不持续灌入新画面触发重复失败。后续通过既有 observe(start) 明确继续，开始新观察代次，不重做旧外部行动。

删除 me.computer.react 模型入口以及依赖它更新的独立“画面解释”字段，不以另一轮模型调用或最终内部文字自动填补。页面继续显示真实预览、采集时间、接管/处理状态与已有关键回执。主体需要解释画面时仍可通过正常显式输出表达；保持安静也可以正常结束本帧处理。这样会减少一个模型工具和一项可选展示，不改变截图、观察、正常聊天/语音输出能力。旧 150 秒缺少 react 回执就暂停的机制由实际输入状态与已确认预算替代，不新增独立模型理解成功保证。

### WebUI 快捷控制与访问范围

**已确认。** 首版产品页面按以下清单实现，精确布局/路由属于后续设计，不复制 Design 画廊作为产品：

| 区域 | 观察内容 | 快捷控制 |
| --- | --- | --- |
| 运行概况 | 宿主/插件就绪或离线、主脑/反思阶段、积压/容量阻塞及当前预算、近期行动关键回执 | 首版以查询为主，不增加任意 Python 执行或模型请求编辑器 |
| QQ 连接 | 连接方式、在线/等待接入/恢复中/恢复耗尽及故障原因 | 明确发起连接恢复；reverse 按监听实际状态解释，不重发旧消息 |
| 收音与播放 | 收音设备/模式/会话、识别状态、实际播放进度及故障 | 选择输入设备和 ASR/原生音频模式，开始/停止收音；独立停止语音输出并取消已有候播 |
| 电脑观察 | 连接、连续观察状态、最后取得的画面及采集时间 | 连接/断开，开始/暂停观察；查询预览不额外截图 |
| 活动 | 目标、实际状态、剩余预算、关键进展和未确认结果 | 暂停、恢复正常已暂停活动、结束；不自动追加预算 |

重启后待核对的活动不能通过普通“恢复”按钮绕过主脑核对；显示中断与待核对事实，仍按既定恢复流程由主脑决定。耗尽/未确认收尾等不可恢复情形显示具体原因，不伪造恢复成功。不在首版面板增加自由创建活动/调整目标的第二套主体调度器。

控制直接提交宿主的同一业务入口，不先请模型判断，不直接写 UI 缓存或数据库。停止收音、停止语音输出、暂停活动分别表达明确动作，不用一个模糊的“停止全部”混合语义。页面及时呈现请求受理、实际收尾和最终确认；控制回执进入同一事实记录，主脑可获知外部明确控制，不出现面板和主脑各有一份状态。重复点击/重连重传依请求身份去重，页面断开不撤销已受理命令。

首版维持观察与控制定位，不新增网页文字聊天通道。文字交互继续现有控制台/QQ；终端详细诊断和独立调音室范围保持已确认约定，主配置编辑按下文“WebUI 产品化扩展”。Live2D 等其他已启用外围显示状态；不默认把每个模型能力都变成按钮。页面遵循 Design 的 StatusMark/Inspector 和真实部分结果表达，不因存在 ApprovalSheet 组件引入产品审批流程。

## 8. 配置、模型适配与诊断

**已确认。** TOML 直接配置凭据，不加入显式环境引用、.env、多来源覆盖或主配置热加载。用 Pydantic 统一配置边界、默认值和程序式构造；主配置及插件各声明语义，应用校验交叉引用。声明为路径的相对配置以主配置文件目录为基准；运行工具参数和独立调音室路径不被任意改写。纯校验不打开服务/设备。配置错误指出字段但不回显秘密；无需凭据的端点按实际契约支持。SDK 隐式环境继承须在适配处核查，不宣称来源唯一却使用另一账号。

**已确认。** 专用判断复用 Core Decisions 与 Purrcept LiteLLM，不迁入第三套通用判断类型/TypeSafe 传输；Engine 保留问题、证据选择和结果解释。普通聊天判断可显式配置，但不伪造概率，也不在专用判断失败时自动换模型。SDK 可见拒答不是 observe 或概率零；不把上游补零/拒答归一化声称为原始网络完整性已验证。旧直接路径与新路径的输入编码/概率处理差异必须验证。

### 配置结构与校验顺序

**委托设计。** 主配置按实际所有者分组；以下只规定结构，不创建 TOML 示例或新增运行初值。已确认数值在各职责章节为单一来源。

| 配置区 | 内容与约束 |
| --- | --- |
| host | 权威数据目录、正常关闭期限、常驻入口选项；单实例约束由宿主执行 |
| models.<name> | 命名的生成或专用判断配置：后端种类、模型标识、端点/凭据、对应模型能力和容量参数。不同后端使用各自合法字段，不能将聊天采样参数传给专用判断 |
| subject | 主体设定，以及前台、反思、摘要、注意等用途到模型配置名的显式引用；可以引用同一配置，不按任务临时寻找替代模型 |
| context / execution / activities | 各自拥有的容量、行动资源/并发及活动预算配置，不在插件里重复声明全局限制 |
| plugins | 唯一实例 ID、明确入口、启用状态及插件自己的类型化配置；内置名称由显式登记表解析，外部使用包入口，不自动扫描启用 |
| console / web / logging / diagnostics | 接入及展示、日志和诊断保留；页面状态不作为配置来源，主配置重启生效 |

模型用途引用解决配置重复，不新增通用服务定位器。活动定义引用启动时登记项；语音设备、QQ 连接及身体校准仍归对应插件配置，不因需要 UI 查询而复制到 web 区。启动时构造不可变已校验配置快照，运行期设备选择等明确控制单独记为状态，不回写主 TOML。

校验顺序为 TOML 语法 → 根结构及字段类型 → 已声明插件配置 → 模型/插件/活动交叉引用与限制关系 → 相对路径解析和依赖可用性。校验不探测模型、网络或设备。缺字段、未知字段、重复 ID 与不相容用途明确报错；插件声明读取必须无启动副作用，不能靠打开连接才能取得 schema。程序式构造经过同一校验，使用相对路径时显式给出基准目录，不随进程工作目录漂移。配置错误定位字段且脱敏，不把 TOML 原始行、Pydantic 输入值或第三方异常原文直接输出而泄露凭据。

**接缝待落实。** 省略 api_key/api_base 在当前 Purrcept 适配层意味着不传给上游，并不表示禁用环境来源；空字符串也不能作为通用禁用方法。Engine 的目标仍是已确认的显式配置来源。需要凭据的实际路径在装配前检查配置；无需凭据的端点须验证其传输确实不借用环境账号，不能用假密钥、临时清空全进程环境或修改 SDK 全局变量假装解决。现有接口能否覆盖该路径应按冻结版本验证，必要 SDK 公共改动另提最小方案，不扩大第 8 节已授权的参数证据改动。未完成该项前不宣称所有 LiteLLM Provider 都满足此约束。

### Purrcept LiteLLM 的限定适配改动

**已确认纳入第二阶段计划，尚未授权实施。** 工具参数证据补齐属于 Purrcept LiteLLM 限定改动，不扩展为 Core/SDK 全面重构。目标是同时覆盖真实流、非流式返回，以及截断/修复/结构验证失败：Engine 可取得 Purrcept 参数修复前的可用材料，并关联最终解析对象或失败原因。这里的“原始”是上游 LiteLLM 交给适配层的参数，不承诺取得未经上游归一化的 HTTP 字节或服务商隐藏内容。

优先复用 Core 现有 ToolCallDelta/ModelResponse.provider_metadata，不新增 Core 公共字段或工具循环。真实流继续在拼装前报告片段；非流式返回的观察事件改为基于转换前参数产生，不从已修复的 ToolCallBlock 反向序列化冒充原文。转换失败时仍能留存已取得参数，不能仅依赖成功 ModelResponse。最终响应可用命名空间元数据补充参数材料的形式、完整性及索引/调用 ID 关联；上游直接给出对象时标记对象形式，不捏造原始字符串。

Engine 为每次尝试安装记录入口，按 request/attempt 与工具索引/ID 关联材料，保存原参数与最终执行参数；重试片段不混合。SDK 只提供可观察值，不写 Engine 数据库、不决定重试、不向模型上下文自动注入审计内容。已有一次 JSON 修复、finish_reason=length 拒绝生成可执行工具调用，以及后续 schema 校验保持现有已确认语义；新增证据不代表新增一轮修复或允许执行半成品。

这会改变非流式合成 ToolCallDelta 的参数内容，并让失败路径也可能产生先行观察事件，属于 SDK 可观察行为变更，须在版本说明和事件测试中明确。成功工具的解析参数和执行顺序应保持；不只通过新增 metadata 存在的测试就声称错误路径已覆盖。记录材料须有边界，超限明确报告证据不完整或请求失败，不静默丢片段后宣称可重建。

重试先用 LiteLLMConfig/default_options 及请求级现有透传配置，在 Engine 固定实际端点路径并控制低层重试；不先新增通用重试 SDK。实际调用次数、取消与共享客户端行为须测试，不能由 max_retries=0 的字面推导保证。若目标端点仍无法通过现有接口满足契约，再提出具体最小调整，不由本次范围确认自动授权修改所有 Provider 或 Core 公共接口。

相邻 SDK 现有未提交变更保持原样；第二阶段开始时先冻结可引用源码状态和候选依赖，再进行接入验证，不自动提交当前工作区来制造发行版本；候选组合见上节，验证失败时不能继续宣称兼容。

| me.live2d.apply(intent) | 保留路径与 intent 参数，输入改为纯语义表达；evidence_id/expires_at/playback_id 不再由模型填写。宿主分配关联与期限；只返回已受理时不能宣称设备已呈现 |
| finish_reflection(reviews, deferred, findings) | 绑定宿主当前批次；结论/知识处理取舍、暂缓及异常评估使用结构化数组，批次 ID 与真实修订 ID/版本由宿主关联。成功返回完成回执及覆盖，普通最后文字不再承载提交协议 |

这些变更中，QQ/浏览器读取参数可省略是为了明确区分首读与 cursor 续读，不取消首读的必需字段校验。source/覆盖信息、内容片段和实际媒体共同计入容量。文本页长度沿配置取得，已确认初值 8000 字符；这只是单页上限，不保证任意模型窗口都装得下。结构化列表不把一个 JSON 对象从中间剪断；大正文有独立片段引用，写操作关键回执不分页。实际取得与向模型交付分开记录：一页无法交付时返回明确的容量信息及已保存原文引用，允许随后请求更小片段，不能静默缩短正文或将引用登记为已读；原工具已经产生的结果/效果不因此改写成未发生。取得/保存本身超限仍按既定规则明确失败。

分页公共字段：evidence_ref 指向不可变原文快照，slice_ref 指向本次交付的实际片段，range 给出该材料格式的范围单位和边界，next_cursor 为宿主生成的后续定位或空值。读完一份快照与外部来源是否完整分别表示。游标绑定快照/版本/呈现方式，不由模型拼接；重复续读取得同一片段，不更新网页或文件。对内容的补充解释不能扩张实际阅读覆盖。

| activity.command | 必需参数 | 不接受的无关参数 |
| --- | --- | --- |
| start | definition、goal | activity_id、additional_seconds、reason |
| pause / resume / end | activity_id | definition、goal、additional_seconds、reason |
| adjust | activity_id、goal | definition、additional_seconds、reason |
| extend | activity_id、additional_seconds、reason | definition、goal |

模型不得提交 command_id；参数缺失、冲突或状态不允许均返回可定位的错误。参数组合检查之外，生命周期/版本、余额与在途收尾仍由宿主实际状态核验，不因模型填对字段就允许执行。

body/intent 沿用现有 BodyIntent 的语义字段：valence 与 gaze_x/gaze_y 为 [-1,1]，arousal/tension 为 [0,1]，gesture 为 none/nod/shake/tilt；对象内未给出的数值字段默认 0、gesture 默认 none，与现有 BodyIntent 默认值一致。省略整个 body 不新增语义姿态，仍允许本地自然动作；不引入新的情绪分类器或情绪枚举体系。附带说话的表达以实际播放开始为采用依据，不从排队时就播放手势；持续姿态跟随当次播放有效，离散手势每次意图只采用一次，声音结束或取消时撤销对应联动。独立姿态的有效时长由配置给出，已确认初值为 4 秒；模型不传绝对单调时钟时间或播放 ID。具体通道到模型参数的校准仍由身体配置负责。

finish_reflection 的 reviews 条目包含 issue、evidence（片段引用数组）、conclusion、memory_decision（written/no_change/defer）与 reason；deferred 条目包含 evidence/reason；findings 条目包含宿主给出的 id、status（confirmed/uncertain）和 reason。复核与整体暂缓范围不冲突；同一范围的知识处理决定不得互相矛盾。written 要匹配本批实际有效修订，无须模型手填 memory_id/version；no_change/defer 仍需理由，不能据此伪造已写入。宿主验证范围与真实效果，不验证结论的语义真伪。该形状替代旧最终 JSON 的重复回执清单，不减少已确认的覆盖校验。

本接口包的必要路径变更为音频停止归属迁移；旧停止路径不另设转发别名，避免关闭收音与停止输出继续耦合。复用的 read/主体工具保持用途边界，不把查原文变成外部获取或自动再次行动。本节字段、返回形状和两个初值已确认，不代表实际提示全文、整份方案或实施已批准。
