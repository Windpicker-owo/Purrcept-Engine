# 主体运行行为

本文说明 Engine 运行期的主体行为、插件能力边界与升级注意事项。
架构与调用链见 [代码架构与调用链](architecture.md)，输入布局见
[输入材料契约](input-materials.md)，构建与分发见 [构建与分发](distribution.md)。

## 源码契约与提示词

开发及注释要求见 [贡献指南](../CONTRIBUTING.md)。公开 Python 接口使用中文
Google 风格契约，先说明用法，再列参数、结果和典型异常；资源、事务、并发与
取消约束集中到 `Note:`。会进入工具描述或 Pydantic schema（含嵌套 dataclass）的
文档属于协议材料，维护者说明放在相邻源码注释中，修改其原文须按模型材料
变更核验。

提示词使用 Core 的 `PromptTemplate`。主体的角色卡、前台、注意和反思定义集中在
[`domain/subject/prompts.py`](../src/purrcept_engine/domain/subject/prompts.py)；摘要、
输入材料和动态提醒布局集中在
[`domain/context/templates.py`](../src/purrcept_engine/domain/context/templates.py)。
调用方准备值，通过 `render()`、`instruction()`、`message()` 或 `reminder()`
取得协议内容。JSON/YAML 与字段树编码仍归序列化层，工具描述继续由 Core
`FunctionTool` 读取方法说明和参数 Schema，不再自行插值提示词正文。

从 `EngineHost` 进入 `EngineAssembly` 查看装配，进入 `SubjectService` 查看注意、
前台与独立后台的编排。`ContinuousSession` 继续借用 Core 的工具循环；
最终文字属于内部结果，只有实际能力调用对外输出。

VS Code 启动配置、decision 预筛选断点与暂停超时说明见
[断点调试指南](debugging.md)。

## 时间与顺序

前台按完整日期、秒与时区核对刺激和行动顺序：每条刺激显式展示来源发生时间
`occurred_at` 与宿主接收时间 `received_at`；每次逻辑请求在插件材料准备后刷新
动态尾部 `request_time.current_time`（附 Unix 秒数），传输重试保持原请求。
行动及逐次调用额外提供可读 UTC 时间，容量引用和迟到回执也保留相应时间。
这些是宿主派发/结果记录，不能冒充平台精确送达时间；跨批历史的位置也不代表
事件实际先后。详情见[输入材料契约](input-materials.md#时间与跨批次顺序)。

## 刺激、注意与唤醒

刺激协调者统一合批、提交和唤醒。observe 将整批保留在主脑收件箱而不立即
唤醒，wake 请求主脑思考，urgent 进一步尝试抢占所观察的旧生成。注意模型是被调用的
批次评估器，不拥有定时、提交或抢占。

收件箱遵循最高级统一原则：一旦出现唤醒级刺激（注意判为 wake/urgent，或可信
高价值输入），整个收件箱随它一起交给主脑，包括 observe 积压、仍在判断中的批次和
合批窗口内尚未判断的输入；不会出现部分批次先交、部分留下的情况。主脑空闲时，
协调者原子取走整个收件箱作为新一轮输入。主脑忙碌时，前台轮次在 Core 每次模型
请求前和每次模型响应后（包括调用工具后、最终回答后）检查唤醒级刺激，并把整个
收件箱作为新的 user 消息并入本轮；工具调用之后到达的输入排在工具结果之后，
已经选定的工具调用不会被撤销。并入的输入沿用本轮剩余请求名额与截止，不重置
预算；本轮已无请求名额时不再并入，留待下一轮。没有唤醒级刺激时，新输入继续
留在收件箱。

urgent 只抢占尚未看到本批的生成：批次已随请求发给模型时不再取消；已并入但还没
发出（例如工具仍在执行）时仍抢占。轮次失败时，中途并入但模型从未回应的输入
不记为失败，而是带着唤醒意图回到收件箱，由下一轮作为完整当前输入处理。

QQ 私聊消息与协议确认的直接 @ 同为最低唤起：通过入站过滤后直接交给主脑，
不等待普通注意合批，也不被 observe 降级。主脑忙碌时只对高价值输入所在
批次进行旧生成紧急升级判断；是否回复、如何回复仍由主脑决定。

注意模型与主脑共用同一份固定角色卡，专用 decision 和生成式注意均可参考
姓名、已有别称、兴趣与关系。群聊中没有 @ 但明确叫主体名字、向其搭话或提问，
规则要求 wake；同名他人、无关引用和重复闲聊仍按语境判断。文字提名继续走普通
注意，不自动升级为私聊/@ 的保底唤起或 urgent，也不要求主体必定回复。

## 主动思考

WebUI 的“系统 → 她的思考 → 主动思考”可随时开关空闲唤醒，默认关闭。
启动默认值在 `[subject]` 设置 `proactive_thinking = false`，空闲间隔由
`proactive_idle_seconds = 300.0` 配置（有限正秒数）。页面修改仅在本次运行生效，
重启采用配置默认值并重新计时，不补发停机期间的周期。
开启后，无新刺激且注意空闲满一个间隔，或主脑轮次结束后空闲满一个间隔，协调者保存
带确切时间和触发原因的 `subject.idle`，保底唤起主脑。新刺激只重置静默期限；
主脑轮次结案才重置空闲期限，成功、失败和抢占使用同一规则。attention/observe 不推迟它，因此持续背景输入也会
定期交给主脑。已有 observe、尚在判断及普通缓存的刺激一并处理；迟到判断按版本
拒绝。主脑忙碌时不生成定时输入，也不累计忙碌期间的周期；结案后重新等待完整间隔。
它不是用户发言，不要求对外回复或行动；关闭不取消已接手的思考或撤回已接管刺激。

## 睡眠

`me.bed.rest(...)` 明确进入睡眠后，普通刺激继续接管但只存历史，attention 停止调用，
只有高优先刺激能唤醒主脑；主动思考暂停且不改变开关。上床所在轮次结束后，
尝试一次上下文压缩，跳过容量阈值但保留近期完整轮次、未决事实和原始证据。
没有可压缩旧历史则跳过，失败保留原历史；领取事实跨重启保存，更新睡眠时长
不会重复压缩。普通睡眠消息不占待处理额度，醒来不会自动整批塞入主脑；原文、
媒体和证据保留，供按需回看与独立反思。已存在的睡眠积压也按此规则仅记历史，
不会阻塞新私聊或 @ 的接管。高优先唤醒不自动起床，显式调用
`me.bed.leave()` 后恢复普通注意，主动思考从完整间隔重新计时。预计睡眠到期
不自动起床或发言。

## 人工行为审查

WebUI 的“行为审查”按时间分页读取持久行动历史，也可从时间线详情进入。
选择行动后可查看发生时所属主脑轮次的全部刺激、原始图片/音频、完整调用参数、
实际回执及行动源码。运行期间后来收到的输入不会误算为当轮刺激；手动或嵌入
行动没有主脑轮次时明确标注，只展示实际关联的输入。

还可切换为真实轮次或能力调用；没有行动的轮次可以评价遗漏回应。
目标结束后可选择“好”或“坏”，并留下最多 4000 字的可选留言，说明原因和
更合适的做法。评价与技术执行结果独立：成功发送的消息也可能是不恰当的行动。
每条评价保留原始留言及所见材料版本；迟到回执不会改写旧评价，提交前材料发生
变化则须重新阅读。评价历史显示最近 32 条，原始评价证据长期保留。

人工评价复用本机控制身份、令牌与原样重传机制，不重复执行被评价的行动。
评价、优先反思来源及主脑可靠投递在同一事务保存；主脑输入额度满时保留待办，
恢复额度后再交接，重启也不丢失。评价请求不会抢占当前生成，主脑通过下一次
唤醒读取指导；反思沿既有独立调度优先复核。已保存不代表模型已经理解或采用。

主脑按情境调整后续行动；局部行为评审对照刺激、真实回执和评价提出有范围、
可观察目标和期限的建议；记忆整理另行判断是否形成长期认识。单次评分不
自动成为普遍规律，意见冲突保留来源与时间；这属于上下文与记忆指导，不是模型
权重训练，也不会直接改写角色卡、执行结果或工具权限。

## Notebook 长期记忆

Markdown 是唯一可编辑的长期记忆。主体通过 `play_action` 使用 `me.notebook.append` 主动记录；
省略路径按宿主本地日期写入 `journal/YYYY-MM-DD.md`。不要求预读哈希，单文件仍受 UTF-8
字节额度约束；超额须显式选择新分片。未知回执先核对文件，不自动重复追加。

动态尾部 `notes_index` 默认最多32条、摘要140字；优先最近两日日记和 `.overview.md`，
不包含正文。`search(query, path="", limit=12)` 只搜索当前笔记；`read(level="summary" | "overview" | "content")`
按需展开，正文分页绑定不可变快照。`description` 仍决定技能身份，`summary` 不会变成技能。
附件不参与记忆整理。

搜索接受最多512字的关键词或自然句。中文长句按相邻双字召回并使用 BM25 排序，
不再把句中的孤立单字全部用 OR 展开；明确的单字查询仍可使用。配置 embedding 后，
关键词与向量排名通过 RRF 融合；纯关键词模式不执行模型请求。
每项结果同时返回摘要、当前文件版本和最多240字的连续原文 `snippet`。
`snippet_range` 使用完整文件的字符半开区间，片段不改写空白、不拼接远处句子；
它在排名等待后的当前版本复核后生成。没有词面对应的语义候选以正文开头作摘录，
并明确标记 `snippet_matched=false`，不伪造命中位置。搜索片段不签发 `slice_ref`，
需要确切引用或更多上下文时继续 `read`。

Notebook 自己持有后台任务。启用时必须显式配置生成模型，默认三十分钟或32次源变更合批，
每批最多32个来源、8次请求及600秒。整理以手写笔记为入口，只展开其中明确引用的
`slice_ref`；不自动扫描全部刺激。后台只更新 `memory/` 中的专题页和概览，不修改原始日记。
专题页区分感受、原话与实际效果，保留来源版本、时间与尚未确定的矛盾。

文件发布成功后登记任务；启动和周期扫描补发现外部编辑。相同内容重复读取幂等，未领取的
旧版本合并到最新版本。生成期间输入或目标变化时拒绝迟到覆盖，失败持久冷却。
文件系统和 SQLite 不构成共同事务；发布意图用于恢复核验，不重放未知写入。
生成页更新只进入索引，不触发新整理，因此不会自激循环。

行为评审只提供原文核对、监管和结案，不承担记忆整理。前台不再有独立 `recall` 工具；
`read_evidence` 继续核对原始交互、回执和媒体。笔记中的约定不代替 `plan_wakeup`，
文字中的“完成”也不代替实际行动回执。

## 输入内容与媒体窗口

输入插件通过 `InputSubmission.with_content(source, blocks)` 交付按原始顺序排列的
TextBlock、ImageBlock 和 AudioBlock。QQ 自行选择必要字段生成 YAML，麦克风交付
原始音频；框架只按来源分组并插入标题，不解析平台字段、不把媒体移动到文字末尾。
模型统一通过 `supports_contents = ["text"]` 声明内容能力，可加入 `image`、`audio`、
`video`；刺激组装将不支持的媒体原位替换为明确文字引用，原件仍保留。
注意与前台分别按各自模型声明投影同一份冻结内容，具体限制及插件示例见
[输入材料契约](input-materials.md)。

连续会话按完整请求大小保留媒体，不再每轮清理两轮以前的媒体。
`[context].media_cleanup_threshold_mb` 默认 30，按 SDK payload 的 UTF-8 JSON 字节数
计量，包含文字、工具声明及图片/音频 base64 编码（1 MB = 1,000,000 字节）。
未超过阈值时保留完整媒体前缀；超限时，一次将已完成历史中的图片和音频
（含嵌套工具结果）原位替换为“历史图片已过期”或“历史语音输入已过期”。
当前轮次的新输入、工具媒体和中途刺激保持完整，超大新输入不会因此被删除；
该配置是清理触发线，不是请求硬上限，token 容量仍独立检查。
会话预检、真实请求和摘要使用相同规则。清理决定在本轮后续请求中保持一致，
成功后保存到连续历史；失败保留原检查点。原件仍可从输入、请求及回执证据追溯。

摘要维护同时检查本地估算和同一份历史的服务端实际输入用量，两者均使用
`summary_trigger` 比例。新输入导致前缀失配时，已有实际用量仍可触发维护；
若已批量清理媒体，则重新计量新布局。实际用量包含旧动态尾部，后续容量计量
只追加新消息及新旧尾部估算的净差值，尾部缩小时可减少规划用量。

未知调用回执默认仅在最近 24 小时内自动保护所在的完整轮次，时长由
`[context].unknown_call_protection_seconds` 配置，从最新 `unknown` 回执时间起算。
超过窗口后，旧轮次允许摘要，回执状态和原始证据继续保留；过期不表示调用成功或失败。
这些旧回执也不再作为当前工作反复附加到动态上下文。仍在执行的调用，以及关联未完成
计划、活动或有效监管的输入，继续按各自业务规则保护。

主体默认装配 `me.view_image(source=...)`，支持URL或本地图像（8MiB以内的
PNG/JPEG/GIF/WebP）；像素完整保存到同库，后续请求通过原生媒体取得。
TOML相对路径沿配置目录，程序式调用未给base_dir时沿数据目录。图片与文字
共用内置 token 估算器，图片按尺寸计量；保存成功不等于已交付像素，仍须通过派发预检。

## 插件能力

内置插件显式启用：`notebook`、`clock`、`bed`、`computer`、`browser`、`meme`、`qq`、
`microphone`（输出）、`voice_input`（收音）和 `live2d`。
可选依赖通过对应 extra 安装，例如 `uv sync --extra qq --extra browser`；
纯配置声明不打开设备，电脑仍须明确连接。Notebook 覆盖写入必须提供读取或
先前写入返回的版本，已有文件不能以省略版本覆盖。QQ 恢复不重发未知消息，
cursor 续读已保存快照，QZone feed 不支持深翻页。

### Notebook 局部编辑

修改少量内容时使用 `me.notebook.edit`，只需输出旧片段、新片段和已读取的文件
版本，保留其他正文。`read` 的第一页即可取得 `version`，无需为修改一个已看到
的片段继续读取整篇。新建文件或明确整体重写仍使用 `write`。

```python
note = await me.notebook.read(path="journal.md")
edited = await me.notebook.edit(
    path="journal.md",
    old_text="待确认：周五见面",
    new_text="已确认：周五 18:00 见面",
    expected_version=note.version,
)
```

`old_text` 必须非空，默认要求唯一匹配，包含重叠位置的歧义也会拒绝；可补充上下文，
或显式使用 `replace_all=True` 替换全部非重叠匹配。`new_text=""` 删除旧片段；
在新片段中保留旧片段并加上新文字即可插入内容。匹配保留空白、换行和 BOM，
不自动做模糊匹配或换行归一化。编辑路径须为精确 Markdown 路径，不解析技能别名。

回执只给出新版本、修改数量及文件元信息，不回传全文；多次编辑可串用上次的
`version`。版本过期、匹配失败或结果超过 UTF-8 字节额度时不发布任何修改。
编辑沿用完整写入的串行所有权、最终版本核验与原子发布；原生发布未知时保留
恢复文件及 `unknown` 回执，不自动重试。外部编辑器仍有最终核验后的竞争窗口。

### QQ 附件与 Notebook

`me.phone.qq.read(chat=..., target_id=..., count=20)` 保存完整历史，默认只分页返回
消息身份、发送者、时间和一份正文。每页正文最多 4000 字符，全局 `page_chars` 更小时
取更小值。原始 OneBot 分段通过 `original_ref` 核对，超长消息通过 `body_ref` 按字符读取。
`next_cursor` 非空时，仅传 `cursor` 继续读取同一快照，不重新请求平台。

贴纸库由宿主默认装配的 `me.stickers` 提供，不再隶属于 QQ。`save(media_id, tag)`
收藏已经读取或上传的实际图片；URL 和本地文件先通过 `me.view_image` 取得媒体引用。
`list(query="猫")` 按标签搜索，省略关键词浏览全库；每页最多 4000 字符，使用
`cursor` 续读原快照。目录只含稳定 ID、标签与媒体元数据，`view(sticker_id)` 才读取像素。
`delete(sticker_id)` 撤销共享收藏，历史消息的图片引用保留。

QQ 的 `save_sticker(message_id=..., tag=...)` 只是从平台收集图片的适配器，写入同一
共享库；发送用 `me.phone.qq.send_sticker(sticker_id=..., chat=..., target_id=...)`。
手机发送用 `me.phone.chat.send(sticker_id=...)`。同图重存沿用身份并更新标签，
不同图片不能抢占同一标签。通用目录入口改为 `me.stickers.list`，不保留 QQ 专用目录别名。
这个共享库归 Bot 使用；APP「我的收藏」归手机用户，保存在手机本地，添加、删除
均不改动 Bot 库。用户发送收藏时按普通图片附件上传，Bot 可再显式决定是否收藏。
Bot 贴纸的唯一索引和完整图片保存在宿主 `engine.sqlite3`。
旧 QQ 的 `sticker_dir` 配置和文件索引已移除，不自动迁移旧目录；已有图片文件
保持原样，可通过 `me.view_image` 读取后重新收藏到共享库。

Bot 可通过 `me.phone.chat.set_avatar(media_id=...)` 设置自己在 APP 中的头像，
图片 ID 可来自 `me.view_image` 或已接管的图片。省略参数或传 `None` 恢复默认。
头像在宿主持久保存，手机离线时也可设置；queued 只证明已保存待同步。
手机联网后下载实际图片并更新顶栏和气泡头像，不改变用户自己的头像和昵称。

QQ 收到语音消息时，在入站过滤和重放核验后下载并解码语音，转换为 WAV 与
消息一起接管；模型声明支持 audio 且容量允许时，原生音频进入输入材料。
单条消息最多读取四段，每段下载最多 20 MiB、解码最多 10 分钟，转换后的
音频合计最多 20 MiB。缺少地址、
下载失败或格式无法解码时，消息仍接管并附上缺口，不假称听到了内容。
遇到 SILK 等本机无法解码的语音时，按平台文件身份请求 OneBot 转码并读取
实际返回的内联音频或 HTTP 地址；平台仅返回远程路径时报告缺口。
重放沿用首次接管结果，不重新下载。此流程不自动转写。

`me.phone.qq.avatar(user_id="123456")` 按 QQ 号生成公开头像 URL，可将返回的
`url` 交给 `me.view_image(source=...)` 查看。生成链接不访问网络，也不证明账号
或头像存在；实际读取失败由看图能力报告。

主体默认提供 `me.listen_audio(source="recording.wav")`，读取本地或 HTTP(S)
来源的 WAV/MP3，按实际容器与解码时长校验，原字节保存为同库证据与媒体。
相对路径沿主配置目录解释；每个文件最多20 MiB、10分钟，不裁剪或自动转写、
不播放声音。取得回执后，原生音频通过工具结果交给后续模型请求，实际模型
端点必须支持音频输入；容量检查与真实呈现资格继续生效，保存成功不等于模型已经听过。
其他编码明确拒绝，不把非 WAV 文件错误标记为 MP3。QQ 附件可先取得文件链接，
直接读取音频 URL，或保存后读取其绝对路径；`media_id` 仅用于原始刺激归因。

QQ 附件可由主体显式保存到 Notebook：`me.phone.qq.file_url` 按实际 `file_id`
取得私聊或群文件链接，再调用 `me.notebook.save_file(url=..., path="attachments/qq/报告.pdf")`。
输入已带 HTTP(S) 链接时可直接保存。PDF、Word、ZIP 等保留原字节，成功回执提供
相对/绝对路径、大小和 SHA256 版本；`tree` 查看目录，`file_info` 查看版本，
`move/delete` 沿用版本核验。下载不覆盖、不自动重试，不解析附件正文或自动装载
附件中的 Markdown 技能。Notebook 配置 `file_max_bytes` 默认 20 MiB、
`file_timeout_seconds` 默认 30 秒，与 Markdown 的 `max_bytes` 分开。
QQ 再发送文件仍受 `extra_media_roots` 等允许目录约束；需要回发时显式加入
Notebook 附件目录。文件链接协议见 [NapCat 文件文档](https://napneko.github.io/develop/file)。

### 中文梗百科与每日提醒

`meme` 插件挂在已声明的 computer 下，提供公开梗检索、详情、本地收藏和收藏列表。
收藏保存首次取得的详情快照，重复收藏不覆盖；离线仍能列出收藏。技能存于 Notebook
的 skills 目录，指导主体遇到疑似梗先检索，空闲时通过浏览器补充出处和使用语境。

每日检查只在 Engine 运行时执行，默认北京时间 09:00。最近扫描窗口有新增或变化
才以 `meme.daily` 提交一条最低 WAKE 刺激，不自动发送外部消息。首次检查介绍当前
窗口；没有变化保持安静。待投原文先落盘，正式接管后才推进已见版本；重启沿用
相同事件身份去重。停机期间不逐日补发，失败退避且保留原因。详细窗口与持久化
边界见[梗百科插件说明](../src/purrcept_engine/plugins/meme/README.md)。

### 电脑截图

`me.computer.screenshot()` 同时保存数据库原图和本地 JPEG，成功回执返回
绝对 `path`，可传给 QQ `send(images=[path])` 或 `send(files=[path])`。
默认目录 `.purrcept/computer-screenshots` 位于 QQ 默认媒体允许范围内；连续观察
不逐帧写文件。配置、失败及文件寿命见[电脑截图说明](../src/purrcept_engine/plugins/computer/README.md)。

`me.computer.command` 在显式连接后以宿主账号运行独立、非交互 PowerShell，工作目录
默认主配置目录，输出有界，回执包含退出码与部分输出。超时或断开会结束本次命令的
完整进程树；已经发生的文件或网络效果不回滚，未知结果不自动重放。取消等待不撤销
已开始命令，原有行动 Worker 隔离规则保持不变。详细参数见电脑插件的宿主命令说明。

### 声音输出与收音

声音输出需要已安装的 FFmpeg/FFplay，配置使用明确程序路径；不会自动安装
或开启声音设备，最小配置见[声音输出](../src/purrcept_engine/plugins/audio/README.md)。
收音需要 `voice-input` extra、明确的设备/模式、固定版本
VAD 文件及 ASR 端点；[收音配置](../src/purrcept_engine/plugins/voice_input/README.md)
说明显式下载与校验步骤，运行宿主不会自动下载。原生音频需要前台声明支持
`audio`；音频按实际时长估算 token，实际派发仍受完整请求输入预算约束。

VAD 持续人声只停止当前及已有候播的语音，不取消主脑生成。起音事件以高优先
停播通知在主脑下一次思考时交付（忙碌时并入当前轮），不单凭此事件发起紧急升级判断；最终语音内容仍沿正常
高价值输入路径处理。通知说明停播请求，实际停止结果及部分播放以音频回执为准。

WebUI“设备 → 收音 → VAD 自动停播”可随时关闭此行为，正常收音和分段继续。
收音插件 `[plugins.config]` 的 `vad_interrupt_enabled = true` 控制启动默认值；
设为 `false` 默认关闭。页面修改仅本次运行有效，不撤回已经发出的停播请求。

### Live2D

Live2D 使用 `live2d` extra、VTS模型校准与人工参数绑定；可选 OVR DLL 只在
独立分析进程加载。音频不借用身体连接，声音开始/终止与视觉采用分别记账。
配置和校准结构见[身体说明](../src/purrcept_engine/plugins/live2d/README.md)。

装配身体注意接收方时，同一注意请求附带情绪、语境注视与各自置信指标；没有身体
接收方时不增加问题。协调者只在批次版本提交成功后交付这些语义，过期或迟到判断
不影响新姿态。身体以本地门槛、注视停留和情绪衰减保持连续表达；显式姿态与播放
字段仍有优先权。此接缝只同步更新视觉目标，不增加世界行动或逐帧模型调用。
VTS 初连与传输失联恢复每轮最多5次，间隔0.5/1/2/4秒；拒绝、协议错误或
次数耗尽停止，退出撤销恢复且不补演旧表达。真实声音与视觉效果待实机确认。

身体意图按字段局部更新：未填写或 null 不改变旧值及期限，显式零值设置中性
目标，gesture=none 取消手势。情绪、注视和一次动作分别存活；播放结束只撤销
该播放仍拥有的字段。新情绪不重启已开始的手势，手势首次发送确认后启动一次。
本地动作控制器使用真实单调时间推进眼头协调、独立头身动力学和分阶段眨眼；
口型继续跟随实际播放器进度。重连清空全部旧目标和速度，模型校准仍需人工观察。

`speak(body=...)` 的 `delivery` 为本次真实播放选择中性、解释、疑问、否定或强调。
PCM 提前到达只准备韵律候选，媒体时钟到位后才选择有限次数的动作；显式手势
优先。交流眉眼与嘴角姿态、持续情绪分别拥有期限和播放归属，结束时只撤回本次
仍拥有的层。`effort` 按次控制轻重，缺省柔和；独立 `live2d.apply` 不接受 `delivery`。
最终口型对当前媒体位置的能量/视素增加开合惯性与短间隙保持，不改变声音时间轴。

## CLI 运行

示例中的模型、凭据和窗口是需要替换的显式字段。`check` 不连接模型或设备；
结构通过不能证明端点容量、媒体支持或实际重试行为。`console = true` 时每行
文字经同一正式接管入口处理；空行忽略，EOF 只结束控制台输入，宿主继续运行。
Ctrl+C 请求关闭，关闭期间第二次 Ctrl+C 强退本 CLI。安装 `web` extra 后可在
`[web]` 设置 `enabled = true`，启动时打印本机面板地址；默认端口 8765，
端口 0 由系统分配。页面刷新只查询已装配宿主，控制经同库身份去重。

## 持久化、日志与关闭

宿主先取得数据目录锁，正式输入原文、媒体与待处理状态同事务保存。
关闭的调用者超时或取消不撤销后台收尾，也不提前释放目录锁。

CLI的普通日志位于数据目录 `logs`，默认七天、每文件10MiB、最多七文件，
通过 `[logging]` 调整。终端只报告中文摘要，文件为结构化诊断，异常仅保留类型、
原因链和位置，不写第三方异常原文、局部变量或请求正文。模型正文默认七天或合计
1 GiB；单次流诊断最多 1 MiB。淘汰后明确报告大小、摘要和原因，不以空正文冒充原件。
输入、行动回执和独立证据按业务生命周期保留。详见 [运行治理](governance.md)。
嵌入入口保留调用者日志配置。关闭故障仍报告原错：已释放的独立资源继续清理，
无法确认归还的资源、权威库和目录锁继续持有。
轮次超时或开始提交结案后，迟到抢占/关闭只等待原结案，不再次取消失败入账。
QQ 与收音分别提供真实资源归还明证；历史输入异常仍报告，但已归还的设备不再
拖住数据库退出。包含取消的故障组同样保留 CLI 的二次 Ctrl+C 处理器。

## 嵌入调用

嵌入调用者可用 `EngineHost.execute` 明确执行行动，结果包括逐次调用回执。
取消等待不会撤销已开始行动；未知结果不能自动重放。插件与替换执行器的
契约分别见 `plugin_system` 的统一入口与协议文档。本机示例为
`examples/action.py`，需要配置启用控制台输出。

## 数据格式与升级

当前格式为17，仅支持16→17的一次性升级；格式15及其他版本明确拒绝且不修改原库。
升级前停止宿主，启动取得目录锁后自动创建 `engine.sqlite3.v16-backup`；若备份已存在，
先核对并移走该备份，再重试。任何校验失败回滚整个升级，保留原库与备份。

升级保留输入、媒体、原始证据、请求审计、前台会话、活动、计划、行为评审与监管。
删除旧认识、冲突关系、记忆整理待办和旧索引，不自动将旧认识导入 Notebook。
旧记忆引用明确不可用；Markdown 原件保持原样，首次扫描重建 Notebook 派生目录和待办。
新旧记忆系统不会同时运行，也不提供双写或兼容转发。
